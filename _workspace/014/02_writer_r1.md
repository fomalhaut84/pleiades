## 1. 무엇을 만드나

```
[외부 앱]  ─┐ HTTPS(B2 · 나중) / 루프백(B1)
[내부 앱]  ─┼─▶ hermes  ──▶ 대기열(디스크) ──▶ 게시 루프 ──▶ Discord #spot (웹훅 하나)
[주기 작업]─┘   ① 인증(출처 키)          ② 검사 · 형식          ③ 재시도 · dead
                                                         └─▶ 수집기가 상태를 읽어 #ops 로(감시)
```

- **받는다:** `POST /v1/messages` 하나(§2). 출처는 **키로 정한다** — 본문의 이름을 믿지 않는다.
- **적는다:** 받은 즉시 디스크 대기열에 쓰고 `202` 로 답한다. 이 시점부터 유실 책임은 hermes 다.
- **보낸다:** 게시 루프가 대기열을 읽어 검사(§3-F) · 형식(§3-E) 뒤 웹훅으로 보낸다. 실패는 백오프로 재시도 · 한도를 넘으면 `dead`.
- **알린다:** dead · 차단 · 대기열 적체는 hermes 가 `#spot` 에 쓰지 않고 **수집기가 `#ops` 로**(§3-G) — 출처의 소음과 운영 신호를 섞지 않는다(D5 의 이유와 같다).

**hermes 가 하지 않는 것:** 양방향(D3) · 출처별 채널 분기(D4 — 필요해지면 §8 Q-H7) · 첨부 파일 · 앱 알림(`ALLOWED`·`ADMIN` 라우트는 notify 그대로 · D5) · 주기 작업 실행(크론은 작업 쪽이 돈다 — hermes 는 받기만).

## 2. API v1 (초안)

```
POST /v1/messages
Authorization: Bearer <출처 키>
Content-Type: application/json
Idempotency-Key: <출처가 정한 문자열 · 선택 · 최대 128자>

{
  "title": "새 주문",                       // 선택 · 최대 100자 · 한 줄
  "text":  "주문 #123 · 5kg × 2 · 58,000원", // 필수 · 최대 1500자
  "link":  { "label": "주문 보기", "url": "https://…" },  // 선택 · 1개(D3) · https 만 · 출처별 허용 호스트(§3-D)
  "level": "info"                          // 선택 · info | warn · 기본 info
}
```

| 응답 | 뜻 | 보내는 쪽이 할 일 |
|---|---|---|
| `202 {"id","duplicate":false}` | 대기열에 적었다 | 끝 |
| `202 {"id","duplicate":true}` | 같은 `Idempotency-Key` 를 이미 받았다(보존 창 안) | 끝 |
| `400` | 형식 오류(필드 · 길이 · `link` 스킴) — 사유 코드만 | 고치기 전에는 재시도하지 않는다 |
| `401` | 키 없음·틀림 | 재시도하지 않는다 |
| `403` | 출처가 꺼졌거나 만료(§3-D) | 재시도하지 않는다 |
| `413` | 본문 바이트 상한 초과(예: 16 KB) | 재시도하지 않는다 |
| `429` + `Retry-After` | 출처별 속도 제한 | 그 뒤 재시도 |
| `503` | 대기열 쓰기 실패 · 종료 중 | **재시도한다** |
| 연결 실패 · 시간 초과 | hermes 가 죽어 있다 | **재시도한다**(같은 `Idempotency-Key`) |

- **보내는 쪽의 재시도는 계약이다.** hermes 가 죽어 있는 동안 온 요청은 hermes 의 대기열이 받을 수 없다 — 무엇을 대기열로 두든(§3-C) 이 구간은 **보내는 쪽 재시도 + `Idempotency-Key` 중복 제거**로만 덮인다.
- **검사 차단(§3-F)은 응답에 드러나지 않는다** — 받은 뒤 게시 루프에서 걸러진다(`202`). 그래야 차단 규칙이 보내는 쪽에 시험당하지 않는다(008 §5-1 "우회 학습 경로" 와 같은 이유). 차단 건수는 수집기가 `#ops` 로 낸다.
- `GET /v1/health` — 인증 없음 · 루프백에서만 · `{"ok":true}` 뿐(대기열 수치는 상태 파일로 · 수집기가 읽는다).
- 버전은 경로(`/v1`)로 — 바꾸면 `/v2` 를 같이 둔다.

**Discord 로 나가는 모양(§3-E):** 웹훅 `username` = 출처의 표시 이름(레지스트리) · 본문 = `**title**` 줄 + `text` + 링크 줄 · `level=warn` 은 앞에 ⚠️ · `allowed_mentions: { parse: [] }`(N3).

## 3. 축별 사다리

각 행의 되돌리기는 **그 축의 선택을 무르는 행위**다.

**권고 A1.** A2 는 체크아웃 하나를 아끼는 대신 가동 중인 통합 층의 배포 경로를 건드린다. A1 의 중복(락·판정 양식·롤백)은 adv 스크립트를 **복사해 이름만 바꾸는** 수준에서 시작하고, 셋째 곁가지 앱이 생기면 그때 공통화한다(§8 Q-H6).

**자동 배포:** adv 와 같은 순서 — 첫 단계는 **사용자 수동 실행만**, 몇 회 통과 뒤 `ssh-deploy.sh` 에 `## hrm` 단계를 더하는 별 PR(G-R4 와 같은 규칙 · 실패가 두 앱 rc 를 바꾸지 않는다 · 효력은 그 다음 Release 부터).

**버전:** 넷째 체크아웃이 없으면 hermes 만 안 뜬다 → adv 판정(N13)과 같이 **minor**. 플랫폼 키 `DISCORD_WEBHOOK_SPOT` 도 선택 키(없으면 게시하지 않는다 · 폴백 없음 · 008 Q98 과 같은 규칙).

| C2 JSONL 추가 쓰기 + 오프셋 파일 | hermes 상태 디렉터리 파일 | 0 | 쓰기 뒤 `fsync` 전 크래시(짧다) | 된다 — 단 중복 제거·dead·압축(compaction)을 손으로 짠다 | 파일 삭제 **즉시** |
| **C3 ★ SQLite outbox**(`node:sqlite` · 파일 하나 · WAL) | 상태 디렉터리 `hermes.db` | 0(데몬 없음) | 트랜잭션 커밋 전 크래시만 | 된다 — 상태(`queued`·`sent`·`dead`·`blocked`) · `Idempotency-Key` 유일 제약 · 보존 기간 삭제가 질의 하나 | 파일 삭제 **즉시** · 코드 **중간** |
| C4 Postgres 테이블(서버 기존 Postgres) | 새 DB 또는 스키마 · 접속 키 | 0(데몬 공유) | 커밋 전 | 된다 — 단 DB 접속 비밀이 hermes 에 생기고 DB 장애가 hermes 를 막는다 · 백업 대상 결정 | DB 삭제(사용자) **중간** |
| C5 Redis Streams · NATS JetStream | 새 데몬 1 | 데몬 메모리·운영 | 설정 따라 | 넘친다 | 데몬 제거 **중간** |

**권고 C3.** 이유:
1. **유실의 두 구간 중 하나만 대기열이 덮는다**(§2): 출처 → hermes 구간은 무엇을 두든 보내는 쪽 재시도가 덮는다. Kafka 를 둬도 hermes 입구가 죽어 있으면 그 사이 요청은 받지 못한다.
2. hermes → Discord 구간은 **받은 즉시 커밋 → 게시 루프 → 성공 표시**의 outbox 로 충분하다. 브로커가 주는 것(분산 · 재생 · 다수 소비자)은 소비자가 hermes 하나라 쓰이지 않는다.
3. 새 데몬 0 · 백업은 상태 디렉터리 파일 하나 · 되돌리기 **즉시**.

**교체 자리:** 대기열은 인터페이스(`enqueue` · `claimNext` · `markSent` · `markRetry` · `markDead` · `purge`) 뒤에 둔다 — 처리량이 필요해지면 C4·C5 로 갈아 끼운다(§9 유효기간).

**U3 가 막으면:** 로컬 node 20.18 에는 `node:sqlite` 가 없다(N12). ① 로컬·CI 를 node 22+ 로(앱 단위 `engines` · CI 매트릭스) ② `better-sqlite3`(네이티브 빌드 · 서버 `npm ci` 에 컴파일) ③ C2 로 내림 — 구현 PR 첫 커밋에서 정한다(§8 Q-H3).

**동작 규칙(C3 기준):**
- 받기: 한 트랜잭션에 행 삽입(`queued`) → 커밋 → `202`. `Idempotency-Key` 는 (출처, 키) 유일 · 보존 창 7일(설계 변수).
- 게시: 한 번에 하나 · 순서 = 받은 순서(출처 사이 공정성은 속도 제한이 맡는다) · Discord `429` 는 `retry_after` 를 따른다 · `5xx`·연결 실패는 지수 백오프(예: 5 s → 10 m 상한) · **시도 N회(예: 20) 또는 경과 24 h → `dead`**.
- 게시 성공 판정은 `?wait=true` 응답(수집기 PR #726 Codex P2 와 같은 이유 — 없으면 저장 못 한 메시지에도 성공).
- 보존: `sent` · `blocked` · `dead` 는 30일 뒤 삭제(설계 변수) — **본문을 오래 두지 않는다**(§3-I).
- 웹훅 키가 없으면(`DISCORD_WEBHOOK_SPOT` 비어 있음) 받기는 계속하고 게시는 멈춘다 — 수집기가 "웹훅 없음" 을 `#ops` 로.

### 3-D. 출처 · 인증

| | 내용 | 되돌리기 |
|---|---|---|
| **D1 ★** 출처 레지스트리 파일(서버 비공개 · 체크아웃 밖) | 출처마다 `id` · 표시 이름 · **키의 SHA-256**(평문 키는 두지 않는다) · `enabled` · `expires`(날짜 · 선택) · 링크 허용 호스트 · 속도 제한 · 표시 아이콘(선택) | 행 삭제 = 그 출처 차단 **즉시** |
| D2 키 하나 공유 | 출처 구분은 본문 이름 | 키 교체 = 전 출처 교체 — D4 의 웹훅 공유 문제를 키로 옮긴 것 · 택하지 않는다 |
| D3 mTLS · 서명(HMAC) | 재전송·변조 방지 | B2 에서 필요해지면(§8 Q-H5) |

- **키 발급·회수는 사용자가 서버에서** — `deploy/hermes/hermes-key.sh add <id>` 가 키를 한 번 출력하고 해시만 레지스트리에 쓴다(Claude 서버 접근 금지 · I-3). 레지스트리 형식은 저장소에 예시 템플릿만.
- **만료(`expires`)** 가 한시 출처의 본체다 — 시즌이 끝나면 따로 지우지 않아도 `403`. 만료 7일 전 · 만료 당일 수집기가 `#ops` 일일 요약에 한 줄(§3-G).
- **레지스트리는 hermes 가 수정 시각이 바뀌면 다시 읽는다**(notify `platformEnv` 와 같은 방식 · 재시작 불필요).
- 내부 앱도 **같은 방식으로 키를 받는다** — 루프백이어도 키 없이 받지 않는다(같은 서버의 다른 프로세스가 출처를 사칭하지 못하게 · B2 로 열 때 예외를 지우는 일이 생기지 않게).

### 3-E. 형식

- **013 의 Discord 형식 규약을 따른다** — 받는 `text` 는 **평문으로 다룬다**: 마크다운 기호 escape(notify `htmlToDiscordMarkdown` 의 텍스트 escape 와 같은 규칙) → 제목만 굵게. 출처가 마크다운을 보내도 서식이 되지 않는다(출처마다 다른 서식 · 링크 위장을 막는다).
- 링크는 `link.label` 을 escape 한 `[label](url)` 하나 · url 은 https + 출처별 허용 호스트(D1) — 허용 밖이면 링크 줄을 빼고 게시(차단 아님 · 건수는 수집기로).
- 길이: `title` 100 + `text` 1500 + 링크 · 형식 뒤 2000자(N3) 넘으면 `text` 를 자르고 `…` (분할하지 않는다 — 스팟 알림은 한 건 한 메시지).
- `username` = 레지스트리 표시 이름 + 접두(예: `spot·`) — Discord 웹훅 `username` 은 "discord" 를 포함할 수 없다(구현 때 확인 · §0-2 에 넣지 않은 이유: 레지스트리 검증 시험으로 고정).

### 3-G. 감시

- hermes 는 상태 파일(`state.json` · 상태 디렉터리)에 **수치만** 쓴다: `queued` · `dead`(누적·오늘) · `blocked`(오늘) · 마지막 게시 성공 시각 · 웹훅 유무 · 만료 임박 출처 id.
- **수집기**가 넷째 체크아웃이 있을 때만 `pleiades-hrm-*` 를 감시 대상에 넣는다(N6 의 adv 방식) — pm2 상태 · 재시작 · `-error` 로그 패턴 · 위 상태 파일. `dead` 증가 · 적체(`queued` 가 N분 이상 줄지 않음) · 웹훅 없음 → `#ops` 경고 · 만료 임박 → 일일 요약 한 줄. **수집기 재설치 필요**(사용자).
- hermes 자신은 `#ops`·`#admin` 에 쓰지 않는다(D5 · 웹훅 하나 원칙 D4).

### 3-H. 내부 출처의 연결 (D2 ②③)

| | 내용 | 되돌리기 |
|---|---|---|
| **H1 ★** 같은 HTTP API(루프백) + 출처 키 | 내부 앱·작업도 외부와 같은 길 · 클라이언트는 `fetch` 몇 줄 | — |
| H2 얇은 클라이언트 `packages/hermes-client` | 재시도 · `Idempotency-Key` · 키를 플랫폼 설정에서 읽기 | 패키지 삭제 **중간** — **내부 출처가 둘 이상일 때**(§8 Q-H2) |
| H3 내부 앱이 대기열(`hermes.db`)에 직접 쓴다 | HTTP 없음 | 스키마가 공개 인터페이스가 된다 · 검사·인증 우회 — 택하지 않는다 |

- **내부 출처 키의 자리:** 플랫폼 설정의 새 키(예: `HERMES_KEY_<출처>`)는 지금 `PLATFORM_KEY_RE`(N1)에 없다 — 넣으면 notify 공개 인터페이스(정규식) 변경이다. 대안: 그 앱의 `.env`(앱 비밀과 같은 자리 · 수집기 ① 대조 대상 `_KEY` 접미에 이미 걸린다 · N4). **권고: 앱 `.env`**(§8 Q-H2).
- **pleiades 안의 주기 작업이 어디 사는가**(새 `apps/<작업>` · `jobs/` · 기존 앱의 크론)는 이 문서 범위 밖 — 작업이 처음 생길 때 정한다. 이 문서가 정하는 것은 **"작업은 hermes API 로 보낸다"** 하나다.

### 3-I. 개인정보 · 보존

- **원칙: `#spot` 에는 사람을 특정하는 값을 보내지 않는다** — 이름 · 주소 · 전화 · 이메일 · 계좌. 주문 알림은 *주문 번호 · 수량 · 금액 · 상태* 와 관리 화면 링크까지. Discord 메시지는 지워도 알림·검색에 남는다.
- hermes 는 이 원칙을 **기계로 강제하지 않는다**(문맥 판단이 필요하다 — 전화번호 정규식 정도는 F1 에 넣을 수 있다 · §8 Q-H8). 출처 등록 런북의 체크 항목으로 둔다.
- hermes 는 본문을 대기열 보존 기간(§3-C · 30일)만 둔다 · 로그에는 본문을 쓰지 않는다(출처 id · 길이 · 결과만).

| R9 | `#spot` 소음이 늘어 아무도 안 본다 | 만료가 기본값(한시 출처) · `level` · 출처별 채널은 Q-H7 |

## 7. 판단 근거 요약 — 왜 웹훅 직접이 아니라 중계인가

출처별 웹훅(이 대화의 첫 안)은 비용 0 이지만 출처가 늘면 ① 검사 없는 외부 텍스트가 채널로 직행하고 ② 끄기·만료가 Discord 설정 손작업이며 ③ 장애 재시도가 출처마다 제각각이다. hermes 는 상시 프로세스 하나의 비용(§4 H-2·H-3)으로 셋을 한 곳에 모은다. 출처가 하나뿐인 동안은 §5 임시 경로와 차이가 작다 — **둘째 출처부터 이득**이다.

## 9. 유효기간

- **출처가 하루 수천 건을 넘거나 소비자가 hermes 밖에 생길 때** — §3-C 를 다시 연다(C4·C5).
- **외부 호스트 출처가 처음 생길 때** — §3-B · Q-H5.
- **양방향(버튼 · 답장)이 필요해질 때** — D3 이 깨진다 · gateway(`packages/chat`) 쪽 설계로 새 문서.
- **서버가 둘 이상이 될 때** — D6 이 깨진다 · §3-A.
- 012 G-R1~R4 · 두 앱 배포 대조 규칙(N7)이 바뀔 때 — §3-A 요건을 따라 고친다.
