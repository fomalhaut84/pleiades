### Q26 · Q19 — **결합 질문이다** (감사 정정 1·2 로 재작성) — **확정: Q26 ① + Q19 C (사용자 2026-09-09)**

두 질문은 1회차에서 독립 항목으로 제시됐다. **그것이 틀렸다.**
**포트 계약을 한 문장으로 쓰면 왜 묶이는지가 보인다:**

> **`BroadcastResult.deliveries[].error` 가 무엇을 담는가 —**
> **(가) raw 문자열**(`error.message` 원문) · **(나) sanitized 문자열**(`sanitizeError` 적용본) ·
> 그리고 **`deliveries[].error?: string`(`003:617`)을 유지하는 한, 호출부가 error *객체* 를 볼 수 있는 유일한 표면은**
> **`NotifyContext.onError?: (target, error: unknown) => void`** 다 (003 §4-2 정정 ③ 개정안 · `003:699`).

`sanitizeError` 는 문자열 함수가 아니다 — **객체를 받아** `.error ?? .cause` 를 **깊이 5(`MAX_DEPTH`)까지 순회**하며
`${name}: ${sanitizeMessage(message)}` 를 만들어 `' | '` 로 join 한다(2회차 재확인: `repos/myFinance/src/bot/utils/error.ts:27-52`).
문자열만 받은 호출부가 쓸 수 있는 것은 **`sanitizeMessage`(`:19-21`, `TOKEN_RE` 치환 1개)** 뿐이고,
**`Name:` 접두도 `HttpError` 내부 체인도 재현되지 않는다.**
∴ **설계 B(raw 포트 + 호출부 sanitize)는 Q26 ② 를 함께 골랐을 때만 성립한다.**

### Q19 — `lastError` 를 포트가 raw 로 담나 sanitize 된 값으로 담나 (1a-1 은 **방향**만) — **확정: C(포트 raw) · 가드는 별건(B′)**

**포트 계약으로 번역한다.** 1a-1 이 정하는 것은 `BroadcastResult.deliveries[].error` 가 **무엇을 담는가** 하나다(위 조합표 서문).

| | 안 | `deliveries[].error` | 호출부 변경 지점 | 관측 변경 | 되돌리기 등급 | 되돌리는 행위 |
|---|---|---|---|---|---|---|
| **A** | 파사드가 sanitize | **sanitized** | **0** (4곳이 그대로 파생) | **5 표면 전부** | **즉시 (1a-3 착수 전까지 · 이후 중간 — 003 §8-1)** / **불가(이미 저장된 행)** | 파사드에서 `sanitizeError` 제거. **단 raw 를 되찾으려면 포트 계약 자체를 바꿔야 한다** — sanitized 문자열에서 원문은 복원되지 않는다. **구현 비용: `sanitizeError` 는 003 §3-1(`003:552`)이 이미 fin 판을 정본으로 골라 흡수 초크포인트(fin `telegram.ts:113`)와 함께 패키지에 들어오므로 A 의 추가 구현은 호출 1개다 — A 를 고르지 않는 이유는 비용이 아니라 5 표면 관측 변경이다** (감사 2회차 권고 2) |

> **B 는 Q26 ② 를 전제한다** (조합표). **Q26 ①·③ 에서 "B" 를 고르면 실제로 도달하는 것은 B′ 다.**
> `deliveries[].error` 열의 *"+ `onError` 로 객체"* 가 그 전제를 표에 박은 것이다.

**실측이 바꾼 것 — 세 갈래.**
1. **위험 등급이 내려갔다.** 현행 유지는 `CLAUDE.md` 컨벤션(형식) 위반이지 **실측 가능한 비밀 노출 경로가 아니다** (C-6).
   `GrammyError.message` 는 메서드명·에러코드·텔레그램 description 만 담고, 토큰 유입 경로는 `HttpError` + `sensitiveLogs` 하나인데 **기본 `false` · 양쪽 미설정**이다.
2. **sanitize 는 안전 강화가 아니다.** `sanitizeError` 의 마스킹 대상은 `TOKEN_RE` 정규식 **하나뿐**(chat id·URL·개인정보는 대상 아님)이고,
   `.error ?? .cause` 를 **깊이 5까지 순회해 `' | '` 로 join** 한다. 결과: `GrammyError` 는 **이름 접두만 추가**, `HttpError` 는 **내부 fetch 에러가 추가된다** —
   **UI·CSV 문자열이 더 길고 더 기술적으로 바뀐다** (C-6). 003 §10 Q19 ③ 이 전제한 *"raw 보존 = UI 문자열 변경 0"* 은 **이 실측으로 확인된다**(뒤집힌 것은 반대편, 즉 *"sanitize = 안전"* 쪽이다).
3. **표면이 하나 늘었다.** 4 → **5** (`retry/route.ts:82`, DB 미경유 API 직접 반환 · C-5).

> **단서 — 되돌리기 열에 반드시 남긴다.** 위 판정은 **`sensitiveLogs` 가 꺼져 있다는 사실에 전적으로 의존한다.**
> 누가 디버깅용으로 `client: { sensitiveLogs: true }` 를 켜면 `HttpError.message` 에 `…/bot<TOKEN>/…` URL 이 붙고,
> **`lastError` 는 마스킹을 하지 않으므로 토큰이 DB·화면·CSV·API 5 표면으로 나간다** (C-6).
> C 를 고르는 것은 **그 가드가 없는 상태를 유지하기로 하는 것**이다.

**권고: 포트는 raw 를 담는다 (C 방향). 최종 적용은 1a-4, 가드는 별건(형태 = B′).**
근거 셋 — **① 은 감사 정정 1 로 교체됐다.**
① **~~raw 는 상위집합이다~~ (폐기)** → **A·B 는 둘 다 포트 계약을 건드려야 도달 가능하다.**
**정확한 서술 (감사 2회차 정정 1 — 이 문장이 003 §10 Q19 정본에 그대로 들어간다):**
> **무조건 0 은 C 뿐 · B′ 는 현 상황(마스킹 대상 0건 — C-6)에서만 0 이고 `sensitiveLogs` 를 켜는 순간 갈린다. 포트를 건드리지 않는 것은 C·B′ 둘 다.**
2회차가 적은 *"관측 변경 0 인 것은 **C 뿐**"* 은 같은 절의 B′ 서술(조합표 · 근거 ②)과 **자기모순**이었다 — 한정어(*무조건*)가 떨어진 것이다.
A 는 `deliveries[].error` 의 내용물을 sanitized 로 규정하는 것이고, B 는 `onError` 표면(Q26 ②)을 포트에 추가해야 성립한다.
raw 포트에서 B 로 "언제든 즉시 이행" 한다는 1회차 서술은 **성립하지 않는다** — 그 이행은 Q26 재결정을 요구하고, Q26 은 1a-4 호출부 20곳이 걸린 시그니처 결정이다.
② **1a 동작 변경 0 을 지킨다.** A 와 B(Q26 ② 조합)는 같은 문자열을 만들고 둘 다 5 표면을 바꾼다.
**관측 변경을 피하는 안은 C 와 B′ 뿐**이고, **포트를 건드리지 않는 것은 C·B′ 둘 다**다 — 다만 **무조건 0 은 C 뿐**이고 B′ 의 0 은 *현 상황* 조건부다(위 ①).
③ **바꿔서 얻는 것이 없다.** 토큰이 없는 현 상황에서 `sanitizeError` 는 안전 이득 없이 **문자열을 길고 기술적으로 만든다** (C-6).
**별건 하나를 함께 등재한다** — `sensitiveLogs` 를 켜면 즉시 노출 경로가 되므로, **금지 룰 또는 `lastError` 마스킹(= B′ 4지점)** 을 별건 이슈로 남긴다.
이 별건은 fin 단독 소규모이고 되돌리기 **즉시**이며 **포트 계약과 무관**하다.

**무엇이 달라지는지**
- **A(파사드 sanitize)**: 호출부는 안 고치지만 화면 2곳·CSV·API 2개의 에러 문자열이 **더 길고 기술적으로** 바뀐다. raw 복원은 포트 변경이 필요.
- **B(raw + 호출부 sanitize)**: 결과 문자열은 A 와 같고 고칠 곳만 4곳 늘어난다. **Q26 ②(onError)를 함께 골라야만 가능하다.**
- **B′(raw + 토큰 마스킹만)**: 지금은 보이는 변화가 0 이고, `sensitiveLogs` 를 켰을 때의 토큰 노출만 막는다. 포트는 raw 그대로.
- **C(현행 보존 · 권고)**: 관측 변경 0 으로 1a 를 끝낸다. 컨벤션 위반은 존치되고, 토큰 가드는 별건(B′ 또는 금지 룰)으로 남는다.

### Q10-L — fit 길이 정책: 절단 → 분할을 1a 에서 받나 — **확정: ① 분할로 통일 (사용자 승인 · 자리는 1a-3)**

> > *"길이 분할은 **변환 뒤**, 즉 `Transport` 경계 안쪽에 있거나, 포트가 "변환 후 길이 예산"을 코어에 알려주는 형태여야 한다"*
>

**실측이 바꾼 것 — 넷.**
1. **초과 가능한 호출은 6 중 1 뿐이다.** fit 아웃바운드 4 모듈 / 6 호출 중 4096 을 넘길 수 있는 것은 **`scheduler.ts:34`(LLM 일일·주간 리포트)** 하나다.
   나머지 5 는 정적 문자열 6종(~60자) 또는 유한 필드 템플릿이고, `admin-alerts.ts:232` 는 `errSnippet = errMsg.slice(0, 200)` 으로 **≈200자 + 고정 6~7줄** 이다 (C-2).
2. **정적 상한이 없다.** `max_tokens`/`maxTokens`/`max_output_tokens` **양쪽 0건**, 프롬프트의 문자 수 지시 **0건**.
   fit 에는 줄 수 지시도 0건이다(`system-prompt.ts:121` 의 정성 문구뿐). **초과 가능성을 정적으로 배제할 수 없고, 빈도도 정적으로는 알 수 없다** (C-2).
