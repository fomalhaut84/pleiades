**C-5 의 소스 선택.** tee 파일(`apps/<dir>/logs/mcp-*.log`)이 아니라 pm2 `-out` 을 고른다 — 두 앱 모두 같은 경로 규칙이고, tee 파일은 체크아웃 안(ignore 된 `logs/`)이라 R-8·체크아웃 교체 영향을 받으며 fin crash 파일은 fit 에 없다(W4). **단 `-out` 줄이 JSON 한 줄씩인지(pino-pretty 등 사람용 형식이 아닌지)는 측정되지 않았다**(S6 은 "stdout 으로 간다" 까지) → §5 추가 측정 X-1.

**web·bot `-out` 은 단계 1 에서 패턴을 보지 않는다.** `console.error`·`console.warn` 은 stderr → `-error` 로 간다(S8 의 호출은 전부 C-4 범위). `-out` 은 C-7 ②(침묵 감지)에만 쓴다.

**시각 창 대신 오프셋.** C5 의 `count_window` 는 줄 앞 19자를 문자열 비교하므로 데몬 TZ = 수집기 TZ 를 전제한다(M2 ③). 상시 수집은 **(inode, 바이트 오프셋) 를 상태로 두고 이어 읽는다** — TZ 비교가 필요 없고, 크기가 줄면(회전·truncate) 0 부터 다시 읽는다. 줄 접두 시각은 표시용으로만 쓴다. 첫 실행은 파일 끝에서 시작한다(과거 로그 폭주 방지).

### 1-2. 지문 (§4-3 의 단계 1 판 · 수집기 내부 형식)

| 출처 | 지문 재료 | 넣지 않는 것 |
|---|---|---|
| C-1 pm2 | `app · role · pm2 · <없음\|status값\|restart>` | pm_id · uptime 값 · 경로 |
| C-2·C-3 health | `app · role · health · <코드 등급: 000\|4xx\|5xx\|timeout>` | 포트 |
| C-4·C-5 로그 | `app · role · stream · 태그 · 오류 클래스 · 코드 · 첫 저장소 상대 프레임` — 각 칸은 허용 문자열일 때만(§1-4) · 없으면 빈 칸 | **메시지 원문** · 숫자·ID·경로가 섞인 나머지 텍스트 |
| C-6 디스크 | `host · <home\|backup> · <usage\|inode> · 임계 단계` | 경로 · 여유 바이트 |
| C-7 자신 | `ops · collector · <원인 코드>` | — |

- 태그 = 줄 머리 `[…]` 의 첫 괄호(S8 상위 `[bot]` `[notification]` `[cron]` — **고정 계약이 아니다**, 그래서 지문 재료일 뿐 분류 기준이 아니다)
- 오류 클래스 = `\b[A-Z][A-Za-z]*Error\b` 첫 일치 · 코드 = `\bE[A-Z]{3,}\b`(예: `ETIMEDOUT`) 첫 일치 · MCP JSON 은 `err.type`·`err.code` 필드가 있으면 그것
- 프레임 = 스택 줄 중 `apps/`·`packages/` 로 시작하는 상대 경로 부분 첫 개(절대 경로 앞부분은 버린다) · 덩어리마다만 시각이 붙으므로(S5) 시각 없는 뒷줄은 앞 줄의 덩어리로 묶는다
- 지문 키 = 위 재료의 SHA-256 앞 12자(게시용 짧은 ID). 재료 자체는 상태 파일에만 둔다
