**web·bot `-out` 은 패턴을 보지 않는다.** stderr 로 가는 줄은 전부 C-4 범위다. `-out` 은 C-7 ② 에만 쓴다(web 은 기본 끔).

**오프셋 규칙(E-8).** 상시 수집은 **(inode, 바이트 오프셋) 를 상태로 두고 이어 읽는다** — 시각 창 문자열 비교(C5 `count_window` · M2 ③)가 필요 없다. 줄 접두 시각은 표시용이다.
- **상태 파일이 없을 때만** 모든 파일을 끝에서 시작한다(과거 로그 폭주 방지)
- 그 뒤 **처음 보는 파일은 0 에서** 읽는다 — 새 pm_id 파일 = 배포가 만든 새 프로세스의 첫 줄부터다(W5 · `deploy.sh:359-361` bot delete→start). 기동 오류가 가장 중요한 순간을 버리지 않는다
- 같은 경로의 inode 가 바뀌면 0 부터 · 크기가 줄면 0 부터(회전은 없다 — V13 · truncate 경로는 사람의 `pm2 flush` 뿐 · K-8)

### 1-2. 지문 (§4-3 의 단계 1 판 · 수집기 내부 형식)

| 출처 | 지문 재료 | 넣지 않는 것 |

| C-2·C-3 health | `app · role · health · <코드 등급: 000\|4xx\|5xx\|timeout>` | 포트 |
| C-4·C-5 로그 | `app · role · stream · 태그 · 오류 클래스 · 코드 · 산출물 파일 경로` — 각 칸은 허용 문자열일 때만(§1-4 ⓪) · 없으면 빈 칸 | **메시지 원문** · 숫자·ID·경로가 섞인 나머지 텍스트 · 줄·열 번호 |
| C-6 디스크 | `host · <home\|backup> · <usage\|inode> · 임계 단계` | 경로 · 여유 바이트 |
| C-7 자신 | `ops · collector · <원인 코드>` | — |

- 태그 = 줄 머리 `[…]` 의 첫 괄호(S8 상위 `[bot]` `[notification]` `[cron]` — 고정 계약이 아니라 지문 재료일 뿐)
- 오류 클래스 = `\b[A-Z][A-Za-z]*Error\b` 첫 일치 · MCP JSON 은 `err.type` 이 있으면 그것
- **코드(E-6) = node errno 이름 목록(`Object.keys(require('os').constants.errno)`)에 있는 값만** — 줄 안의 `\bE[A-Z0-9]+\b` 후보 또는 MCP JSON `err.code` 가 그 목록에 있을 때만 쓰고, 목록 밖이면 빈 칸. (`\bE[A-Z]{3,}\b` 는 `ERROR`·`EMPTY` 와 E 로 시작하는 종목 티커에 맞아 개인 도메인 값이 Discord 로 나간다 — 008 §5-1 "원인이 그 값일 때만" 위반 경로)
- **프레임(E-5) = 산출물 상대 파일 경로만** — 운영 프로세스가 도는 것은 빌드 산출물이고(`pleiades.config.cjs:63`·`:76`·`:81`·`:97`·`:105` — web `.next` · bot `dist/bot/standalone.cjs` · mcp `dist/mcp/server.cjs`) `--enable-source-maps` 가 없다(`:61`·`:63`·`:64-71`) → 스택 프레임의 줄·열·청크 이름은 **빌드마다 바뀐다.** 그래서 `:<줄>:<열>` 은 버리고, `.next/server/chunks/*`·`app/**` 청크는 칸을 비운다(이름 자체가 빌드마다 다르다). **이것은 소스 위치가 아니다** — 008 §4-3 의 "저장소 상대 위치" 는 단계 1 에서 얻을 수 없고 단계 2(구조화 이벤트)로 미룬다(F-7). 절대 경로 앞부분은 버린다 · 시각 없는 뒷줄은 앞 줄의 덩어리로 묶는다(S5)
- 지문 키 = 위 재료의 SHA-256 앞 12자(게시용 짧은 ID). 재료 자체는 상태 파일에만 둔다
