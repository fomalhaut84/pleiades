### 3-2. 트리거 · 대상 · 원장

**넘김.** T1 ★ 상주가 수집기 상태를 **읽기만**(수집기 무변경). D0 에서 읽는 것: `state.json`(후보 · 메타) + `events.jsonl`(⑤ 에만) + 배포 표지 · 창 파일. T2 요청 파일 · T3 `ask` **중간** · T4 Discord 경유 **배제**([M14] [M26]).

**메타 = 분석 입력의 전부(D0 · r4 · C8).**

- **판별은 원 객체, 입력은 투영.** 대상 판별(아래 ①~⑤)은 state 지문 원 객체(`posted` · `deferred` · `postedQuiet` 등)를 읽는다. 분석 입력은 **`FP_SHAPE` 투영**(ops-shape `fp` 의 required + optional 키만) **+ 명시한 숫자 칸 하나 `횟수`** 다. 버림 목록 `fp.ignored` 를 그대로 공유하지 않는다 — 그 목록은 판별 칸과 횟수 원천까지 버린다([M54]).
- **횟수 원천 = 지문 `days` 객체의 값 합**(관측 수 · 숫자가 아닌 값은 버리고 키는 입력에 넣지 않는다). `firstCount` · `pending` 은 쓰지 않는다. 칸 이름은 상수 하나.
- **원문 위험 칸 상수 `RAW_FIELDS` = `material` · `detail` · `scope`** 를 통합 층에 따로 둔다. 시험 셋: ① ops-shape `fp.ignored ⊇ RAW_FIELDS` ② 투영 결과에 `RAW_FIELDS` 키 0 ③ detail · material · scope 에 표지 문자열을 둔 state 로 입력을 만들면 그 문자열이 입력 바이트에 0. 수집기가 지문 키를 더하면 ops-shape 쪽 시험이 먼저 깨진다(015 V27 경로 그대로).
- 그 밖에 입력에 드는 것: 그 앱 **태그(아래 규칙)** · 재분석이면 원장의 첫 분석 시각 · 첫 심각도.
- 메타 칸 원천은 원문 0 으로 확인됐다([M53]).

**태그 규칙 (r4 · C1 · C9).** 앱마다 한 값.

| 상태 | 태그 값 |
|---|---|
| pending 없음 · last-ok 본문이 `TAG_RE`(릴리즈 태그 형식 상수) 일치 | 그 값(확정) |
| pending 있음(③ 에서 낡은 경우만 여기까지 온다) | **`미확정`** — pending 값을 쓰지 않는다([M49]: 트리가 그 태그라는 보장이 없다) |
| last-ok 없음 · 읽기 실패 · `TAG_RE` 불일치 | **`미확정`** |

원장 · 메타 · 결과 표지 모두 이 값만 쓴다. 표지 파일 본문이 그대로 모델에 가는 길은 `TAG_RE` 일치 하나뿐이다.

**대상 판별 (r4).** 한 주기에 이 순서로 거른다.

| 단계 | 판별 | 근거 |
|---|---|---|
| ① 후보 | `deferred` 아님 · `postedQuiet` 아님 · `posted` 가 숫자 · 심각도 [X1] | [M27] |
| ② 제외 | 수집기 자기 이상 `ops·collector·*` · `all-missing` · 통합 층 자신(`adv`) | SV:63 · SV:76 |
| ③ 배포 상태 | 그 앱 pending 이 **[M43] 이내**면 그 앱 보류(원장 안 씀). **낡았으면** 분석 재개 · 태그 = `미확정` · 메타에 `배포 실패 잔류`. 낡음 판정은 수집기와 같은 상수 · 같은 비교식([M43]) — **시험 범위는 저장소의 소스 상수 + 비교식까지**다. 운영 수집기는 체크아웃 밖 커밋 고정 설치라 판 차이는 시험이 못 본다(C2 · §8 · §0-2) | [M25] [M43] [M49] |
| ④ 원장 | 없음 → 새 분석 · 있으면 재분석 규칙 | — |
| ⑤ 차단 제외(권고) | events 에서 그 지문의 행(`first` · `repeat` 어느 것이든)에 `blocked` 가 하나라도 있으면 분석 안 함 · 원장 `차단` · [M45] 로 못 읽으면 그 주기 분석 0 + 관리자 알림 정적 문구 1회. **잔여(AU3 범위 밖):** dry-run 행엔 `blocked` 가 안 붙어 dry-run 기간의 비밀 후보 지문은 이 제외를 빠져나간다 — D0 에서는 새 문자열이 없어 보수 규칙의 구멍일 뿐 · ⑤ 를 권고로 두는 이유는 r3 그대로(빼면 events 를 안 읽는다 — Q156) | [M27] [M45] |

**폭주 묶음.** 같은 `posted` 시각의 지문을 한 분석으로([X8]) — 비용 절약일 뿐 · 입력은 메타.

**분석 원장.**

- 위치: 통합 층 비공개 디렉터리([M38]) · 임시 → rename · 쓰는 프로세스 하나.
- 값: 지문 → 첫 분석 시각 · 첫 심각도 · 그때 태그(확정 값 또는 `미확정`) · 결과 id · 상태(`시작` · `완료` · `형식 실패` · `차단` · `건너뜀` · `중단`).
- **순서 고정(C7):** 원장 `시작` 쓰기 → 예약 → 세션 실행 → 정산 → `완료`(또는 `형식 실패`). **`시작` 쓰기가 실패하면 예약도 실행도 하지 않는다.** 재기동 뒤 남은 `시작` = `중단` · 재실행 없음 · 예약이 있었으면 그날 쓴 것으로 남는다(보수 · 이중 청구 0).
- **재분석 규칙(r4 · C1 · C10).** 원장에 있으면 분석하지 않는다. 예외 — 아래 셋이 모두 참일 때 한 번 더:
  1. **현재 태그가 확정**이고 원장 태그와 다르다. **`미확정` 은 어떤 태그와도 같지 않다**(원장이 `미확정` 이면 다음 확정 태그와 다르다) — 다만 **현재가 `미확정` 이면 재분석하지 않는다**(같은 `미확정` 끼리 매 주기 도는 것을 막는다).
  2. 지문 `last` 가 C5 창 t0 보다 뒤. **t0 변환:** [M52] 의 문자열을 서버 시간대 상수(수집기의 KST 날짜 가정과 같은 상수 하나)로 epoch ms 로 바꿔 비교 · 형식이 수집기 창 정규식과 다르면 창 없음으로 본다.
  3. ③ 에서 보류가 아니다.
- **잔여 위험:** 창 파일이 없거나(첫 배포) 표지 쓰기가 실패한 배포에서는 재분석 1회를 놓친다 — 원장 기록은 남고 사용자는 `!분석` 으로 본다.
- 시험: 원장 `미확정` → 확정 V 통과 + `last` > t0 → 재분석 1회 / 현재 `미확정` → 0 / t0 경계(직전 · 직후 `last`) / 창 형식 불일치 → 창 없음.
- 보존 [X6] > [M4]([M39] 로 키가 릴리즈마다 새로워지지 않는다). **처음 켤 때** 기존 후보를 전부 "본 것" 으로 적는다.
- **원장 손상:** 그 주기 분석 0 · 관리자 알림 정적 문구 1회 · 고치거나 지우는 것은 사람.

되돌리기: 원장 삭제 **즉시**(처음 켬 규칙) · 규칙 revert **중간**.
