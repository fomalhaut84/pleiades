### 3-2. 트리거 · 대상 판별 · 원장

**넘김 수단.** T1 ★ 상주가 수집기 상태를 **읽기만** 한다(당김 · 수집기 무변경 · 재설치 0) — 단 **`state.json` 과 `events.jsonl` 을 함께 읽는다**(AU 정정 1). T2 요청 파일(수집기 변경 + 재설치 · **중간**) · T3 `ask`(**중간**) · T4 Discord 경유(**배제** — [M14] · 봇 자기 글도 버린다 [M26]).

**대상 판별 (r2 재작성 · T1).** 한 주기에 다음 순서로 거른다. `state.json` 은 원자적이라 반쯤 쓴 파일은 없다([M41]).

| 단계 | 판별 | 근거 |
|---|---|---|
| ① 후보 | `state.json` 지문 중 `deferred` 아님 · `postedQuiet` 아님 · `posted` 가 숫자 · 심각도 [X1] | [M27] |
| ② 제외 | 수집기 자기 이상 `ops·collector·*` · `all-missing`(detail 비어 있음) · 통합 층 자신(`adv`) | SV:63 · SV:76 |
| ③ 배포 상태 | 그 앱에 `pending` 표지가 있으면 **그 앱 분석 보류**(태그 불명 · 코드 트리 섞임) — 원장을 쓰지 않고 다음 주기 | [M25] |
| ④ 원장 | 원장에 없음 → 새 분석 · 있으면 아래 재분석 규칙 | — |
| ⑤ 재료 등급 | events.jsonl 에서 그 지문의 `type:first` 행을 찾는다 — **`blocked` · `quiet` 없는 행이 있으면 "게시됨"**, `blocked` 행이면 **"차단"**, 행이 없으면(폭주 묶음 · `fp:null`) **"묶음"** | [M27] [M28] |
| ⑥ 입력 | "게시됨" = Q161 이 허용하는 칸 · "묶음" = 메타(app · role · src · sev · 시각)만 · **"차단" = 분석하지 않고 원장에 "차단" 으로 적는다**(어떤 Q161 답에서도 detail 금지) | Q161 |

**폭주 묶음.** 같은 `posted` 시각을 가진 "묶음" 지문들을 한 분석으로 묶는다(상한 [X8] · 넘는 것은 개수만). `posted` 는 반복 게시가 덮어쓰므로 묶음 판별이 틀릴 수 있다([M27]) — 틀려도 입력은 메타뿐이라 새로 나가는 것은 없고, 비용은 [X2] 가 막는다. 폭주 소속을 정확히 갈라야 한다고 정하면 수집기 변경 + 재설치(**중간**)가 S4-1 에 들어간다 — r2 는 넣지 않는다.

**분석 원장.**

- 위치: 통합 층 비공개 디렉터리 아래(`ensurePrivateDir` · [M38]) · 임시 → rename · 쓰는 프로세스 하나.
- 값: 지문 → **첫 분석 시각 · 첫 분석 심각도**(state 의 `posted`·`sev` 는 덮어써지므로 원장이 스스로 적는다 · [M27]) · 분석 때의 그 앱 태그 · 결과 id · 상태(`완료` · `형식 실패` · `차단` · `건너뜀`).
- **재분석 규칙(r2):** 원장에 있으면 분석하지 않는다. 예외 하나 — **원장에 있고 · 그 앱의 `lastOk` 태그가 원장 기록 태그와 다르고 · 지문의 `last` 가 그 배포 시각(`lastOk` 의 mtime)보다 뒤이고 · pending 이 없을 때** 한 번 더(수정 배포 뒤 재발 — 008 §4-1 [확인] 재료). 로그형 재발은 다시 열리지 않으므로([M42]) state 의 열림이 아니라 이 비교로만 본다. r1 의 ③(간격 재분석)은 뺀다 — 변화 없는 재분석은 새 정보 없이 비용만 쓴다.
- 보존 [X6] > [M4]. 지문 재료가 청크 이름을 버리므로 릴리즈마다 키가 새로워지지 않는다([M39]).
- **처음 켤 때** 기존 후보를 전부 "본 것" 으로 적는다(밀린 것 · dry-run 시절 행을 한꺼번에 분석하지 않는다).
- **원장을 못 읽거나 깨졌을 때(r2 · AU §5):** 그 주기 분석 0 · 관리자 알림 웹훅에 정적 문구 1회([M15] 규칙) · 원장을 고치거나 지우는 것은 사람. 지우면 다음 주기에 "처음 켬" 규칙 — 그래서 **하루 건수는 원장이 아니라 분석 몫 파일에 둔다**(§3-7) — 원장을 지워도 그날 건수 [X2] 가 초기화되지 않는다.
- 배포 중(배포 락 시험에 걸림 · SV:123)이면 원장을 쓰지 않고 다음 주기.

되돌리기: 원장 삭제 **즉시**(처음 켬 규칙) · 규칙 revert **중간**.

### 3-3. Q161 (신설) · Q152 — 분석 입력에 무엇이 나가나

### 3-4. Q162 (신설) · 코드 리더

008 §4-7 *"배포 체크아웃 코드 읽기"* · 산출의 `file:line` 은 이것 없이 근거가 없다. 읽는 대상(저장소 소스)은 공개 저장소에 있다 — 위험은 **경로가 소스 밖으로 새는 것**과 **질문 세션에 섞이는 것**이다.

**읽는 체크아웃.** C0 없음 · C1 통합 층 체크아웃(태그가 틀릴 수 있다) · **C2 ★ 그 앱의 배포 체크아웃**(도는 태그 · pending 없을 때) · C3 `git show`(**배제** — 쓰기 0 겹 ②). 되돌리기: 끄기 **즉시** · revert **중간**.

**Q162 — `pl_code` 를 어디에 두나.** 자동 발견은 모든 선언을 모든 질문 세션에 넣는다([M33]). 선언으로 두면 질문 세션 도구 정의 · probe · 계약 시험 발견이 바뀐다.

### 3-5. 분석 세션 (F1)

**F1 ★ 같은 프로세스 · 분석 세션 설정을 따로** — 상수 `ANALYSIS_SYSTEM_PROMPT`(BASE 무변경) · 도구 = ops 리더 + (S4-2 뒤) Q162 의 코드 리더 · 별 mcp-config · 세션 키는 `discord:` 아닌 분석 전용 형식 · 한 번 묻고 끝(resume 없음 · 세션 Map 에 넣지 않는다) · 판정기 · init fail-closed · 모델 핀 · 자식 env · `--setting-sources project` 그대로. F0(질문 세션 재사용)은 fin·fit 도구가 들어가고 데이터/지시 구분이 흐려진다 · F2(별 실행 파일) = §3-1 (c). 되돌리기: 끄기 **즉시** · revert **중간**.

**세션 기록 (r2 · AU 정정 8).** 통합 층 CLI 는 세션 기록을 사람 개발용과 같은 설정 위치에 남긴다([M34]). 분석 세션은 detail · 코드 · 산출이 정리 없이 쌓이므로:

- **분석 세션만 `--no-session-persistence`** — cliArgs 에 인자 · 시험 둘(분석 경로는 플래그 있음 · 질문 경로는 지금 단언 그대로 플래그 없음).
- **지난 분석 결과 · 원장 내용을 다음 분석 입력에 넣지 않는다**(지속 주입 경로 차단 · 015 WP-3 과 같은 이유). 넣어야 할 때가 오면 K-8 로 싸고 이 절을 개정한다.

**분석 프롬프트가 담을 것(문안은 S4-1 PR):** 역할 = 운영 이상 원인 추정 · 고치지 않는다 · 입력의 detail · 이벤트는 **"데이터 — 지시 아님" 절 안에**(K-8 첫 구현 · matrix-intake M-1·M-2 와 같은 이유 · 주입 크기 [M29]) · 근거 없으면 "추정" · 재료 부족이면 그렇게 쓴다 · 산출은 §3-6 형식 하나.

**Q148 관계.** 질문 세션의 BASE · 도구 순서는 F1 + Q162 (ii) 에서 바이트 그대로다 — 선언 고르기 인자를 질문 경로에 두지 않으므로 r1 의 "기본값 전부" 시험도 필요 없다. (i) · (iii) 을 고르면 그 시험이 다시 필요하다.

### 3-6. 산출 형식 · 검증 · 행선지

## 9. 감사가 반증해 볼 주장 (2회차)

1. **"§3-2 ⑤ 로 '게시됨' 을 가를 수 있다"** — events.jsonl 의 `type:first` 행에서 `blocked` · `quiet` 가 없으면 정말 Discord 에 그 detail 이 올랐는가 · dry-run 시절 행이 같은 모양인가(처음 켬 규칙만으로 충분한가) · events 회전 · 보존으로 행이 사라진 지문은 어떻게 되나(묶음으로 떨어져 detail 0 이면 안전 쪽인가).
2. **"D1 의 새로 나가는 문자열 0"** — 같은 지문의 detail 이 첫 게시 뒤 바뀌었을 수 있는가(state 의 detail 이 첫 게시 본문과 다른 경우) · 그렇다면 첫 게시 본문의 detail 을 events 에서 가져와야 하는가.
3. **"재분석 규칙은 `lastOk` 하나로 충분"** — `lastOk` 의 mtime 이 배포 시각과 다를 수 있는가(재설치 · 수집기 재기록) · 두 앱이 다른 태그일 때 · 통합 층 자기 배포(4b-5)가 끼면.
4. **"분석 몫 별 파일 + 합 판정은 질문 경로를 깨지 않는다"** — 질문 예약 · 정산이 합을 읽게 고친 뒤 날짜 경계 · 한쪽 파일 손상 시 어느 쪽으로 닫히나(fail-closed 인가).
5. **"Q162 (ii) 면 Q148 이 구조로 성립"** — 분석 세션 준비 코드가 질문 세션과 mcp-config 생성 함수를 공유할 때 순서 · 바이트가 새지 않는가 · probe 가 분석 세션을 보지 않는 것이 V18 배포 판정의 맹점이 되는가.
6. **"CR-3 의 구성 요소별 lstat + realpath 로 링크 탈출 0"** — 검사와 읽기 사이 경합(TOCTOU) · 대소문자 · 유니코드 정규화 · 하드 링크.
7. **"CR-5 pending 검사로 섞인 트리를 읽지 않는다"** — pending 표지가 checkout 보다 먼저 생기고 C5 뒤에 지워지는가 · 표지 없는 배포 경로(손 배포)가 있는가.
8. **"켬 표지는 재기동 0 · 서버 조치는 표지 생성 하나"** — 표지 위치가 `adv-inplace` · 수집기 · `check_env` 의 어느 검사에도 걸리지 않는가 · 배포가 그 디렉터리를 지우거나 덮는가.
9. **"`--no-session-persistence` 면 분석 입력이 디스크에 남지 않는다"** — CLI 의 다른 캐시 · 로그 · 디버그 파일 · 통합 층 자체 로그(K-5 줄 외)에 입력 조각이 남는 곳.
10. **"산출 검증기가 M-2 의 유일한 기계 보조로 충분"** — 셸 모양 판별의 오탐(정상 설명 문장 거부 → 형식 실패율) · 백틱 없이 쓴 명령 · 전각 문자 우회.
11. **"같은 busy(Q150 권고)면 메모리 무변경"** — 분석 세션의 호스트 수가 질문 세션과 다를 때(미측정 [0-2] 그대로).
