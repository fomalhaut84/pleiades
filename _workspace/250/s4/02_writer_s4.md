**분석 원장 (수집기 판정과 독립).**

- 위치: 통합 층 비공개 디렉터리 · 600 · 임시 → rename · 쓰는 프로세스 하나(상주).

- 재분석 규칙: ① 원장에 있으면 분석하지 않는다 ② 단, 그 앱의 **배포 태그가 바뀐 뒤** 다시 열리면 한 번 더(수정 뒤 재발 — 008 §4-1 [확인] 의 재료) ③ 마지막 분석에서 [X7] 이 지났으면 한 번 더. 태그를 어디서 읽는지는 미측정(§0-2) — 못 읽으면 ② 를 끄고 ③ 만.
- 보존 [X6] > [M4] — 수집기가 지운 뒤의 재발이 새 분석이 되지 않게.
- 상태형 재열림 · 14일 뒤 재발 · 폭주는 전부 원장이 거른다(§1 첫 행).

### 3-4. 코드 읽기 도구

008 §4-7 *"배포 체크아웃 코드 읽기"* · 산출의 `file:line` 은 이것 없이 근거가 없다. **읽는 대상(저장소 소스)은 공개 저장소에 이미 있다** — 위험은 코드 내용이 아니라 **경로가 소스 밖으로 새는 것**(`.env` · 비공개 디렉터리 · 로그 · 생존 표지)이다.

### 3-6. 산출 행선지 · 게시 검사 · 형식

**형식 (단계 5 이슈 본문과 같은 모양 — 008 §4-7 · §4-8 단계 5 행).** 모델은 **정해진 JSON 하나**를 낸다 → 통합 층 코드가 검증한다(알 수 없는 키 거부 · 칸 길이 [X10] · 열거형 칸은 값 목록):

| 칸 | 형식 |
|---|---|
| `fp` · `app` · `tag` | 코드가 채운다(모델 값 무시) |
| `cause` | 원인 추정 · 짧은 문장 |
| `confidence` | `높음` · `중간` · `낮음` · `재료 부족` |
| `evidence` | 이벤트(시각 · 지문) · 저장소 상대 `file:line`(CR-2 허용 목록 경로만 · 아니면 그 항목을 버린다) |
| `fix` | 해결 방안 — **제안**(M-1) · 명령·URL 칸 없음(M-2) |
| `repro` | 재현 조건 · 선택 |

검증을 통과하지 못하면 결과를 버리고 원장에 "형식 실패" 로 적는다(재분석하지 않는다 — 재작성 재시도 없음 · 008 §5-1 과 같은 이유: 우회 학습 경로).

**행선지.**

| **R0 ★(S4-1) 파일만 + 통합 채널 코드 명령** | 결과 = 통합 층 비공개 디렉터리 파일 · 사용자가 통합 채널에서 코드 명령(예 `!분석 [지문]`)으로 본다 · 먼저 보내지 않는다 | 통합 채널 답과 같은 노출 등급(사용자 한 명 · 지금 답도 `checkPost` 를 거치지 않는다) — 단 출력에 §5-1 ②③ 을 코드에서 한 번 건다 | 파일 삭제 **즉시** · 명령 revert **중간** · 채널에 보인 글 **중간** |

## 9. 감사가 반증해 볼 주장

1. **"T1 은 수집기 무변경"** — `state.json` 지문 항목에서 commit 된 것 · 폭주에 묶인 것 · 미뤄진 것을 실제로 가를 수 있는가(§0-2 미측정). 못 가르면 T2(수집기 변경 + 재설치)로 올라가고 S4-1 의 서버 조치가 0 이 아니게 된다.
2. **"E0 에서 새로 나가는 것은 이미 Discord 에 있던 것"** — detail 조각 말고 분석 입력에 들어가는 것(이벤트 행 · 코드 리더 결과 · 모델이 검색한 소스)이 정말 원문 0 인가 · stderr tag 자유 문자열([M5])로 만들 수 있는 주입 문구의 크기.
3. **"(a) 는 하루 상한 파일의 단일 쓰기 전제를 지킨다"** — `!분석` 명령 · 정지 표지 · 원장 · 상한 파일이 같은 프로세스 안에서도 겹쳐 쓰일 수 있는가(질문 정산과 분석 예약의 순서).
4. **"F1 은 Q148 과 충돌 0"** — "선언 고르기" 인자를 넣은 뒤에도 질문 세션의 시스템 프롬프트·도구 순서가 바이트 동일한가 · 발견 순서(`id` 정렬)에 영향이 없는가.
5. **"R1 은 `checkPost` 단일 출구를 지킨다"** — 수집기가 모델 산출물을 게시하면 검사 ① 의 대상(두 앱 `.env` · 플랫폼 설정)이 충분한가 · 통합 층 체크아웃 `.env` 는 대조하지 않는다(008 §2 2026-11-17 블록)는 범위 밖 규칙이 모델 산출물에도 안전한가.
6. **"C2 의 위험은 경로뿐"** — 대상 앱 체크아웃 안에 소스 밖 비밀이 소스 경로 모양으로 있을 수 있는가(예: 소스 디렉터리 아래 생성 파일) · 심링크 거부만으로 충분한가 · 통합 층이 다른 체크아웃을 읽는 것이 012 G-R1~R4(체크아웃 경계)와 부딪히지 않는가.
7. **"분석은 기본 꺼짐이라 S4-1 은 minor · 서버 조치 0"** — 켜기 env 키가 통합 층 env 허용 목록(#696)·`check_env` 에 걸리는지 · 켜는 순간 필요한 서버 조치가 #199 "서버 조치" 칸에 무엇으로 적혀야 하는지.
8. **"같은 busy(Q150 권고)면 메모리 무변경"** — 분석 세션의 mcp-config · 호스트 수가 질문 세션과 다를 때 RSS 가 정말 같은 범위인가(015 미측정 그대로).
9. **"원장 보존 [X6] > [M4] 면 재분석 폭주가 없다"** — 지문 재료(`material`)가 릴리즈마다 바뀌는 경우(산출물 경로가 청크 해시를 포함하면) 원장 키가 매번 새로워지지 않는가 · 그때 하루 건수 상한 [X2] 만이 비용을 막는가.
10. **"쓴 비용만 편도"** — 분석 산출이 R0 에서 통합 채널에 보인 것 · R1 에서 `#ops` 에 오른 것(중간) 외에, 산출 파일이 나중에 질문 세션·대시보드·단계 5 의 입력으로 다시 들어가는 길(015 WP-3 과 같은 지속 주입 경로)이 생기는가 — 생기면 K-8 이 그 경로에도 필요하다.
