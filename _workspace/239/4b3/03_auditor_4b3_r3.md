## 3. 정정 (3)

### 정정 1 — 실패 뒤 **직전 태그로 되돌리기가 rc 1 로 막힌다**(A 표 8행 "태그 ≠ V · pending ≠ V → rc 1")

- 상황: W 배포가 C3~C6 에서 rc 4 로 끝나면 HEAD = W(태그) · pending = W · last-ok = V(직전) 가 된다. r2 §4 가 적은 되돌리기 "직전 태그로 재실행"(`adv-inplace.sh V`)은 정확히 이 행에 떨어져 **rc 1** 이 된다. 결과적으로 남는 복구는 "W 재실행 또는 `stop`" 뿐이고 **되돌리기가 없다**.
- release-inplace 는 이 경우 R-8 을 허용한다. P = W ≠ V 이면 pending 과 무관하게 checkout 으로 진행한다(`:202-207`). pending 은 "이미 배포됨" 판정(`:196`)에만 쓰인다.
- 고치는 방법:
  - **HEAD 태그 = pending(≠ V)** 이면 실패한 배포를 되돌리는 것이다 → 진행(C2 checkout V). 양식에 "되돌리기 — 실패한 W 뒤" 를 적는다.
  - rc 1 은 **pending 이 HEAD 와도 V 와도 다를 때만** 낸다(체크아웃이 손으로 옮겨진 경우).
  - 시험 1줄.

### 정정 2 — `stop` 뒤 같은 태그 재실행이 "이미 배포됨" rc 0 으로 끝나고 **봇을 띄우지 않는다**(A 표 3행)

- 상황: `stop` 은 last-ok 를 그대로 두고 `-stopped` 를 쓴다. 그 뒤 HEAD = V · last-ok = V · pending 없음 상태에서 `adv-inplace.sh V` 를 다시 실행하면 3행 "이미 배포됨 rc 0" 에 걸린다. 그러면 pm2 에 adv 가 없는 채 **다시 켜는 방법이 다른 태그뿐**이다. 수집기도 `-stopped` 때문에 침묵한다.
- 고치는 방법: "이미 배포됨" 은 **`-stopped` 가 없을 때만** 낸다. `-stopped` 가 있으면 C3 부터 진행한다(빌드는 이미 있어도 그대로 다시 한다). 9행 "= V · = V · = V" 도 같은 조건을 붙인다. 시험 1줄 · 런북 "정지 뒤 다시 켜기 = 같은 태그로 실행".

### 정정 3 — `stop` 은 "무조건 · 즉시" 가 아니다: adv 가 없으면 실패하고, 데몬이 없으면 **빈 덤프로 두 앱의 resurrect 목록을 덮는다**

- `pm2 delete <없는 이름>` 은 0 이 아닌 코드로 끝난다. 그래서 두 앱 배포도 `|| true` 로 감싼다(`deploy.sh:360`). r3 `stop` 행에는 이 처리가 없다. 그대로면 "adv 가 이미 없을 때(첫 실행 실패 · 크래시 뒤 delete) stop 실패" 가 된다.
- **pm2 데몬이 없을 때**(재부팅 뒤 resurrect 전 · 데몬이 죽은 뒤 — G-R3 가 이미 가정한 상황): `pm2 delete` 가 **빈 새 데몬을 띄운다**. 이어지는 `pm2 save --force` 는 프로세스 0개를 `~/.pm2/dump.pm2` 에 쓴다. 그러면 **fin·fit 의 resurrect 목록이 지워진다**(D6 — dump 는 통째 저장). 다음 재부팅에서 두 앱이 뜨지 않는다.
  - 배포 경로는 C1b 의 fin·fit 대조가 막는다. 단 그 대조가 release-inplace 처럼 **`n_same > 0`(`:248`)을 요구할 때만**이다. r3 문구 "fin·fit `env_same` 판정" 에 이 조건을 명시해야 한다.
  - `stop` 경로는 그 대조를 건너뛰므로 막는 것이 없다.
- 고치는 방법:
  - `stop` 은 먼저 `~/.pm2/rpc.sock` 이 있는지 본다(수집기가 같은 이유로 CLI 를 부르지 않는다 · `collect.cjs:181-184`). 없으면 pm2 를 전혀 부르지 않고 `-stopped` 쓰기 · alive 삭제만 하고 통과한다(양식 "데몬 없음 — pm2 무변경").
  - 데몬이 있으면 `jlist` 에서 adv 가 있을 때만 `delete` + `save --force` 를 하고, 없으면 `save` 하지 않는다.
  - 배포 경로 C1b 에는 "fin·fit `pleiades-*` 가 1개 이상 same(`n_same > 0`)" 을 적는다.
  - 시험 3줄: 데몬 없음 · adv 없음 · fin·fit 없음 상태의 배포 rc 1.
  - 되돌리기는 그대로 **즉시**다.

## 4. 문안 (3)

1. **"양식은 서브셸 안에서만 1번"** → "**한 실행에 1번**". 0 · C1a · L 에서 멈추면 바깥에서 내고, 그 뒤는 서브셸 안에서 낸다. 바깥은 서브셸이 돌았으면 양식을 다시 내지 않는다.
2. **`stop` "즉시"** → "즉시 — 단 두 앱 배포가 락을 쥔 동안(수 분)은 rc 1, 끝난 뒤 다시". 락은 `stop` 에도 맞다(정지 도중 두 앱 배포와 겹치지 않게).
3. **9행 "= V · = V · = V"** 의 뜻이 release-inplace 와 다르다는 것을 적는다. release-inplace 는 이 상태를 "끝나지 않은 시도" 로 본다(`:196` · PR #294 — 성공한 태그를 `--retry` 로 다시 하다 실패한 경우). adv 표에서는 3행이 같은 태그 재실행을 받지 않으므로(정정 2 반영 뒤에는 `-stopped` 일 때만 받는다) 이 상태는 "last-ok 쓴 뒤 pending 삭제 전 중단" 하나로만 생긴다 — 그래서 r3 처리가 맞다. 다만 **`-stopped` 뒤 재실행(정정 2)** 이 실패하면 이 상태가 다시 생긴다. 정정 2 의 진행 경로는 C2 앞에서 pending = V 를 쓰므로 실패하면 (V, V, V) 가 된다. 그 경우 9행에 걸려 "이미 배포됨" 으로 덮인다. → **9행도 `-stopped` 가 있으면 진행**으로 하거나, 끝 단계 순서를 "pending 삭제 → last-ok 쓰기" 로 바꾸고 9행을 없앤다.

## 5. 보충 (2)

1. **표가 덮지 않는 상태 · 기본값.**
   - ① 비태그 · last-ok 없음 · **pending = V**: 첫 실행이 pending 을 쓴 뒤 checkout 에서 실패하거나 끊긴 경우다. 1행(pending 없음)에도 2행(last-ok 있음)에도 걸리지 않는다 → 1행의 pending 을 "없음 또는 = V" 로 넓힌다.
   - ② 태그 = V · **last-ok = U(≠ V)** · pending 없음(손 checkout): 5행은 last-ok 없음만 다룬다 → 진행(C3 부터)으로 합친다.
   - ③ 표 끝에 **"그 밖 = rc 1(양식에 HEAD · last-ok · pending)"** 을 둔다. 그래야 "전 경우" 가 문장 하나로 보장된다.
   - 시험은 행마다 1줄씩 둔다.
2. **adv 가 다시 활성이 될 때 오프셋.** 비활성 동안 adv 파일 오프셋을 남기지 않으면(r3) `stop` → 재배포로 다시 활성이 될 때 `readNew` 가 adv `-error` 로그를 **처음부터** 읽는다. 그러면 정지 전 줄이 한꺼번에 관측으로 나온다(같은 문제를 PR #590 이 첫 회 처리로 막았다 · `collect.cjs:429-431`). 앱이 **비활성 → 활성으로 바뀐 회**에는 그 앱 파일의 오프셋을 끝(`st.size`)으로만 두고 읽지 않는다. 시험 1줄.
