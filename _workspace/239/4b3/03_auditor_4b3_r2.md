## 3. 정정 (3)

### 정정 R2-1 — C1 사전 대조와 last-ok 확인이 **adv 자신의 복구와 `stop` 을 막는다**

- 주장: C1 `env_same` 을 "release-inplace C1 과 같은 식"으로 쓰고, adv 가 아직 없을 때만 그 줄을 뺀다. `stop` 도 C1 → L 을 거친다. W1 의 복구는 "스크립트 재실행" 이다. 4b-3b 런북 줄은 "`pleiades-adv-bot` DIFF/MISSING → adv 스크립트로 재기동" 이다.
- 코드: release-inplace 식은 **모든 `pleiades-*`** 를 센다(`release-inplace.sh:89`). 그래서 adv 가 다른 env 로 떠 있으면(W1 상황 · 바로 그 복구가 필요한 때) adv 스크립트 자신이 C1 rc 1 로 멈춘다. 재배포도 `stop` 도 안 되고, fin·fit 배포도 C1 rc 1 에서 멈춘다(012:275). **복구 경로가 남지 않는다.** `stop` 에 fin·fit last-ok 확인이 걸려도 같다. 정지는 정상 상태에 기대지 말아야 한다.
- 제안:
  - 사전 대조는 **`pleiades-adv-bot` 줄을 빼고** fin·fit 줄만 판정한다. adv 자신의 불일치는 정보 줄 "(재기동으로 고친다)" 로 남긴다.
  - `stop` 은 C1 의 `PLEIADES_PRIVATE_DIR` 거부와 L(락)만 거친다. 사전 대조와 last-ok 확인은 거치지 않는다.
  - 시험 2줄: adv DIFF 상태에서 배포가 통과한다. fin·fit last-ok 가 없어도 `stop` 이 통과한다.
  - 되돌리기는 그대로 **중간**이다.

### 정정 R2-2 — B5 합계 가드는 "예약 **전**" 에 판정할 수 없다(B7 ① 순서)

- 주장: B7 ① 순서 "상한 판정 → 합계 가드(B5) → `reserve`" · B5 "모델 호출 전 · 사용액 0 — 예약 전에 판정".
- 코드: 시스템 프롬프트는 `Advisor.startSession` 안에서 만들어진다. 도메인 읽기 경로 응답이 있어야 크기를 안다(`advisor.ts:99-118` · `buildSystem` `:110`). 그런데 예약 자리는 라우터(`bot.ts:80-97`)이고 `advisor.ask` 를 부르기 **전**이다. 지금 배치로는 가드가 예약보다 먼저 올 수 없다.
- 제안(둘 중 하나를 고른다):
  - (i) 가드를 `ask` 안의 거부 사유(`refused` · 새 reason)로 둔다. 예약은 그대로 두고, `costOf(refused) = 0`(`bot.ts:58`)이라 정산 −1.00 으로 순 0이 된다. 바뀌는 파일 없이 문구만 고치면 된다.
  - (ii) 예약을 `Advisor` 안, `runOnce` 직전으로 옮긴다(`DailySpend` 를 Advisor 의존으로).
  - 권고는 (i)이다. B5 문구를 "사용액 **순 0**(예약 뒤 거부 → 정산)" 으로 고치고 시험도 맞춘다.

### 정정 R2-3 — 수집기 adv 게이트가 어긋나면 수집 한 회 전체가 예외로 멈춘다

- 주장: B9 "감시 조건 … · `LOG_NAME` 에 `adv-bot`".
- 코드: `collectLogs` 는 `LOG_NAME` 에 맞는 **모든 파일**마다 `ctx.deploy[app].held` 를 읽는다(`collect.cjs:417,428`). `ctx.deploy` 는 `deployWindow` 가 `APPS` 키로만 만든다(`:208-223`). `stop` 뒤에도 `~/.pm2/logs/pleiades-adv-bot-*.log` 는 남는다. 그 상태에서 adv 를 감시 집합에서 빼고 `LOG_NAME` 에는 남기면 `ctx.deploy.adv` 가 undefined 가 된다. 그러면 TypeError 가 나고 **fin·fit 판정을 포함한 그 회 전체가 실패**한다.
- 제안: 활성 앱 집합 하나(`activeApps()` — fin·fit + 조건부 adv)를 한 번 계산해 7곳이 모두 그것만 쓰게 한다(`expected` · `deployWindow` · `collectLogs` 파일 선택 · health · glob-empty · alive · silence). `LOG_NAME` 에 맞더라도 활성 집합 밖의 앱 파일은 건너뛴다(오프셋 상태도 남기지 않는다). 시험 1줄: `-stopped` + adv 로그 파일 존재 → 예외 없음 · fin·fit 판정 그대로.

## 4. 문안 (3)

1. **B1 "Actions 배포가 같은 위치를 쓴다는 증거"** — last-ok 가 있다는 것은 "**어느 때인가** release-inplace 가 이 위치를 썼다" 는 뜻이다(`v1.0.2` 손 배포 기록일 수도 있다). 증거를 세게 하려면 내용을 대조하는 1줄을 둔다: `inplace-fin-last-ok` 내용 = `~/pleiades-fin` HEAD 태그(fit 도 같다). 다르면 rc 1 이 아니라 (주의) 줄로 둔다(R-8 도중일 수 있다). B11 줄과 합친다.
2. **§3 (b) 의 거부 조건** — hooks 뿐 아니라 user settings 의 **`mcp__` allow · 와일드카드 allow** 도 모든 질문을 막는다(`settings.ts:35-36,80`). 개발 중에 allow 를 넓히는 일이 hooks 보다 흔하다. W6 도 같이 고친다.
3. **C1 사전 대조 위치** — release-inplace 는 락을 잡은 뒤 C1 을 한다(`:181` → `:242`). r2 는 L 앞에서 한다. 락 밖 대조는 그 사이 시작한 배포를 못 본다(그 경우 L 에서 rc 1 이라 해는 작다). 서브셸 안, L 뒤로 옮기면 release-inplace 와 같은 순서가 되고 pm2 호출도 저절로 fd 9 없이 돈다.

## 5. 보충 (4)

1. **A 단계 상태 표.** r2 는 세 경우만 정했다(같은 태그 + last-ok · last-ok 없음 + 비태그 · last-ok 있음 + 비태그). 빠진 경우는 이렇다.
   - **rc 4 뒤 같은 태그 재실행**(HEAD = V 태그 · pending = V · last-ok ≠ V 또는 없음): 체크아웃 없이 C3 부터 다시 해야 한다. release-inplace 는 이 경우에 `--retry` 를 두었다(`:189-208` · PR #283·#294 Codex P2 이력).
   - **첫 실행 실패 뒤**(HEAD = V 태그 · last-ok 없음): 위 규칙 어디에도 걸리지 않는다.
   - 표로 정하고 시험을 둔다. 첫 실행 실패의 되돌리기는 "직전 태그" 가 없으므로 **`stop`** 이다. 런북 · 양식의 복구 줄에 적는다.
2. **4b-3a1 조건 — FATAL 로그 줄을 그대로 둔다.** `[<label>] gateway 종료 코드 <n>` 은 `discord-inbound.sh:31,136` 의 판정 문자열이다. 콜백은 그 줄을 **찍은 뒤에** 부르고 문구는 바꾸지 않는다. chat 시험에 "콜백이 있어도 줄 동일" 1줄을 둔다.
3. **서브셸 rc · 양식 · 트랩 규칙.** 양식(`emit_form`)은 서브셸 안에서만 낸다. 바깥은 `( body ) 9>&-; exit $?` 한 줄로 rc 만 넘긴다. 락 해제 트랩(mkdir 폴백)과 `INT TERM HUP` 트랩은 바깥에 둔다(bash 는 `( )` 안에서 트랩을 초기화한다). 시험 1줄: 서브셸 안 rc 4 가 스크립트 rc 4 로 나오고 양식이 1번만 나온다.
4. **동적 fd 시험의 `node` 스텁.** 스크립트는 `env_same` JSON 파싱과 probe 에 진짜 node 가 필요하다. 그래서 스텁은 `[ -e /dev/fd/9 ]` 를 기록한 뒤 **진짜 node 로 exec** 하는 래퍼여야 한다(pm2 스텁도 jlist 출력을 흉내 내야 한다 — release-inplace 시험 방식). 바깥 셸의 L 앞 단계(정정 R2-1 · 문안 3 반영 뒤에는 없어진다)에서는 fd 9 가 원래 없으므로 기록 0 이 당연하다. 시험은 "락 뒤" 호출만 센다는 점을 적는다.
