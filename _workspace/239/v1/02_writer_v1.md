## 3. 계약 v1 — 도메인 → 기능 제공자

### 3-1. 제공자 종류 사다리 (누가 서빙하나)

| 옵션 | 무엇 | 맞는 제공자 | 이득 | 비용 | 되돌리기 |
|---|---|---|---|---|---|
| P-a v0 유지 · 모든 제공자가 앱 상주 MCP | hermes 에 MCP SDK + `/mcp/read` · 수집기에 상주 MCP 프로세스 신설 · 위키 MCP 프로세스 신설 | fin · fit 만 자연스럽다 | 계약 한 모양 | 수집기·위키에 **새 상주 프로세스 2**(pm2 이름 · 포트 · G-R1~R4 와 묶임 · 012 R-15) · hermes 에 의존 추가 · 서버 조치 | 프로세스 정지 **즉시** · 코드 revert **중간** |
| **P-b ★ 두 종류: `mcp`(앱 상주 · v0 그대로) + `local`(통합 층이 띄우는 읽기 호스트)** | `local` = 통합 층 코드 안의 **리더**가 선언된 데이터만 읽어 MCP 도구로 낸다 · 호스트는 CLI 자식 stdio MCP(권고 · 포트 0) 또는 통합 층 안 루프백(대안) | fin · fit = `mcp` · hermes(H1·H2) · ops · 위키 = `local` | 새 상주 프로세스 0 · 새 포트 0(stdio 일 때) · 판정기·허용 목록은 그대로 MCP 도구(V30) | 리더 코드가 통합 층에 쌓인다(제공자의 데이터 모양과 결합 · 아래 원칙) · stdio 동작 미측정(§0-4) | `local` 제공자 선언 삭제 · revert **중간** |
| P-c 통합 층이 파일을 직접 읽어 시스템 프롬프트에 붙인다(도구 없음) | MCP 를 거치지 않는 "맥락 주입" | 수치 상태만 | 가장 싸다 | 매 세션 비용 · 위키(search · read_page 요구 · #837)에 안 맞는다 · 묻지 않은 데이터가 늘 실린다 | revert **중간** |

**권고 P-b.** 이유: 비데이터 제공자 셋 모두 "작은 읽기 몇 개" 이고, 셋 다 같은 서버 같은 HOME(V28)이라 통합 층 프로세스가 읽을 수 있다. 상주 프로세스를 늘리는 순간 012 R-15(통합 층이 두 앱 배포를 멈춘다)의 결합이 하나씩 더 붙는다(014 §3-A 가 이미 hermes 에서 겪었다).

**`local` 리더의 원칙 (V28 이 만든 것).** 700/600 은 장벽이 아니다 — 같은 사용자라 통합 층은 `.env` 도 읽을 수 있다. 그래서 **범위는 코드가 지킨다:**
1. **읽을 위치는 리더 코드의 상수**다 — 선언 파일(JSON)에 경로를 두지 않는다(선언은 리더 id 만 고른다). 선언 하나 고쳐 다른 파일을 가리킬 수 없게.
2. **필드 허용 목록**으로 거른다 — 알 수 없는 필드는 버린다(제공자 쪽 형식이 늘어도 새 필드가 모델로 새지 않는다).
3. 리더는 읽기만 한다(열기 플래그 · 잠금 없음) · 크기 상한 · 깨진 줄은 건너뛰고 개수만 로그.

## 13. 감사가 반증해 볼 주장 (싸다고 한 곳 위주)

1. **"AD-1 로 새 앱의 통합 층 쪽 수정이 7 → 1(A28 만)로 준다"**([W1]) — A12 문구 생성 · A25 glob · A27 판별 스키마가 실제로 "새 앱 = 무변경" 인가. 특히 `auto-inputs.txt` glob 을 `ssh-deploy.sh` 의 `git diff -I` 비교가 그대로 받는가(미측정).
2. **"V-2 는 동작 무변경(minor)"** — 스캔 순서 · BASE 문구 변경이 두 도메인 답을 바꾸지 않는가. 문구 변경은 답 입력이다(012 4a-3a 의 "앱 개발 문서가 답의 입력" 과 같은 함정).
3. **"`local` 호스트(stdio)는 포트 0 · 서버 조치 0"** — CLI 자식으로 뜬 stdio 서버가 통합 층 자식 env 허용 목록(012 4b-3 확정 블록)과 `judgeInit` 서버 수 대조(V12 · SV:37)를 통과하는가 · 배포 락 fd 9 를 그 자식이 물려받지 않는가(012 G-R3).
4. **"`propose` 는 C1 의 예외가 아니다"** — 제안 대기열 쓰기가 사실상 모델이 통합 층 디스크에 쓰는 길이다. 크기·개수 상한 · 주입된 제안이 승인 화면에서 사용자를 속이는 경로가 남는지.
5. **"O2 는 수집기 재설치 0"** — 리더가 `events.jsonl` 형식에 묶이는데, 수집기는 커밋 고정 설치라 저장소 판과 서버 판이 다를 수 있다(설치 REF ≠ dev). 형식 고정값 시험이 그 차이를 잡지 못한다.
6. **"H1 은 hermes 코드 0"** — `state.json` 을 다른 프로세스가 읽을 때 hermes 의 쓰기 방식(원자적 rename 인지)이 확인됐는가 · 부분 파일을 읽으면.
7. **"init 미연결 제공자를 빼고 한 번 다시 열면 비용 0"** — V12 의 "비용 0" 은 init 단계 실패 기준이다. 재시도가 세션 프레임 고정(V14) · resume 세션과 어떻게 맞물리는가(이미 열린 세션의 serverKey 집합이 바뀐다).
8. **"S0 예산 가드는 안전 쪽"** — 지식을 뺀 제공자로 답하는 것이 전체 거부보다 나은가(모델이 지식 없이 도구를 잘못 해석한 답이 게시되면 편도).
9. **"V-5 · V-6 은 서로 독립"** — 둘 다 V-4 호스트와 판정기 serverKey 형식에 묶인다 · 둘이 같은 릴리즈면 실패 원인이 섞인다.
10. **"Wk-a 는 기존 비공개 규칙 무변경"** — `ensureWikiDir` 이 위키 루트를 비공개 루트 **아래**에 둘 때, 같은 루트 아래 다른 파일의 기존 `insideGit` 검사가 위키의 `.git` 을 조상으로 보지 않는가(위키 하위가 아니면 조상이 아니지만, 위키를 비공개 루트 자체로 두면 전부 깨진다).
