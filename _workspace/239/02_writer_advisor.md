## 0. 한 줄 요약

**통합 어드바이저는 도메인(fin · fit · 일정·비서 · 개발·운영) 위의 별도 층이다.** 지금 교차 도메인 경로는 0 이고 그것을 막는 것은 앱 코드가 아니라 실행 위치다(W6). 그래서 **먼저 앱 코드 변경 0 · 서버에서 사용자가 실행하는 1회성 실험**으로 *"쓸 만한가"* 만 판정하고, 쓸 만할 때만 축 A~I 를 확정해 구현한다. 선결은 fin 대화 지연 기준선(#624) 하나다.

## 4. 축별 옵션 사다리

등급: **즉시**(설정·프로세스 정지·키 삭제) · **중간**(코드 revert + 릴리즈 · 며칠) · **높음**(이력·데이터가 얽힘) · **편도**. 소요는 이 저장소에 실작업 시간 기록이 없어 등급으로 갈음한다(workflow 4절).

### 4-1. A. 오케스트레이터 위치

| 옵션 | 무엇 | 이득 | 비용 | 되돌리기 |
|---|---|---|---|---|
| **A0** 오케스트레이터 없음 | 에이전트 1개가 모든 도메인 읽기 도구를 갖고 한 번에 답한다 | 추가 호출 0 → 지연·비용이 대화 1건 그대로 · **실험 형태가 이것** | 도메인이 늘면 도구 목록이 계속 커진다(영향 미측정) · 도메인 지식(K-3)을 한 프롬프트에 다 실어야 한다 | 즉시(설정) |
| **A1** 전역 1 · **코드 라우팅** | 채널 ID·명령·정규식으로 도메인 힌트를 정하고 A0 에이전트에 힌트·도구 범위를 넘긴다 — LLM 판단 없음 | 추가 호출 0 · 현행(앱 봇 라우터의 명령·정규식)과 같은 방식 · 결정적 | 교차 질문을 단일 도메인으로 오분류할 수 있다 → 힌트는 "기본 맥락"이지 도구 제한이 아니어야 한다(C1·C3) | 즉시~중간(라우팅 표 · 코드) |
| **A2** 전역 1 · **LLM 라우터** | 소형 모델 한 단이 요청을 분류해 도메인 에이전트(들)에 넘긴다 | 모호한 요청·여러 도메인 요청을 나눌 수 있다 | **대화 1건마다 한 단 추가** — S1b 판정 2: 추가 비용·지연은 사람 대화 경로에 붙는다 · 얼마인지 미측정 | 중간 |
| **A3** 채널별 오케스트레이터 | 채널마다 자기 오케스트레이터 | 채널 맥락이 강하다 | 사용자 방향 *"채널마다 별도 어드바이저 없음"* 과 긴장 · 교차 질문이 채널에 묶인다 | 중간 |
| **A4** 혼합 | A1 이 기본 · 분류 불확실할 때만 A2 | A2 의 이득 일부를 비용 일부로 | 두 경로를 다 유지 · 경계 판정이 새 결함 표면 | 중간 |
