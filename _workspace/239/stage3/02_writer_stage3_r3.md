> **r3 의 형식 변경 (AU2 §5 권고).** 두 번 정정된 주장(배포 락 A-3 → R2-B·R2-C · 허용 키 A-8 → R2-D)은 원인이 같았다 — **공유 자원의 다른 사용처를 빠뜨렸다.** r3 는 공유 자원 넷(배포 락 · 허용 사용자 키 · `pleiades-*` pm2 이름 공간 · 플랫폼 키 정규식 거울)의 **사용처 전수 표를 §0-5 에 한 번** 두고, 본문은 그 표의 행을 가리킨다. 표는 작성자 정적 grep 이고 명령을 함께 적었다 — 3회차 감사가 같은 명령으로 확인할 수 있게.
번호: 011 의 마지막 미결 Q132 다음 **Q133** 부터. 대장 행은 **[N#]** 로 가리킨다.

> **이 초안의 규칙.** 숫자는 §0 대장에만 적는다(workflow 2절) — 본문은 [N#] 로 가리킨다. 대장의 "파생" 행은 **원 행에서** 계산하고 식을 함께 적는다(반올림한 파생을 다시 곱하지 않는다 · A-14). 측정자가 재지 않은 값은 "미측정" + 재는 방법. 설계 변수는 대장 D 절에 "선택" 으로 따로 둔다. 되돌리기 등급: 즉시 / 중간 / 높음 / 편도 — 소요는 등급으로 갈음한다(workflow 4절).

> **r1 에서 바뀐 큰 줄기 (감사 1회차).** ① G7 은 두 앱 배포와 **세 가지로 묶인다**(공용 forced command · `PLEIADES_ENV_FILE` 일치 · pm2 이름 접두) — r1 의 *"운영 배포 경로 무변경 · 위험 0"* 은 틀렸다(A-1). 권고는 유지하되 그 셋을 설계 요건으로 고정하고, 자동 배포 단계를 처음부터 넣지 않는다. ② 4c-2 는 "질문 판정 규칙 공용화" 가 아니라 **앱 봇 → 통합 층 새 경로**다 — 통합 봇은 앱 라우팅 우선순위와 fit 편집 대기를 볼 수 없다(A-6). ③ 허용 사용자 목록은 세 봇이 공유한다 — 다중 사용자 확장 요구를 지키려면 **통합 층 전용 키**가 필요하다(A-8).

> **r2 → r3 (감사 2회차).** ① 요건 위반은 늘 "바꾸기 전" 에 멈추지 않는다 — 배포 도중 env 불일치·앱 접두 이름은 **C5 에서 바꾼 뒤** 멈춘다(rc 4 · 새 태그로 서비스 중 · `--retry`) → 위반 결과 표(§3-4)와 기동 시점 거부(R2-A). ② 배포 락 fd 를 자식에서 닫는 요건(R2-B) · 상주 시험은 잠깐 잡는다(R2-C). ③ 전용 허용 키는 정규식 3(R2-D). ④ 로컬 pm2 리허설은 하지 않는다(R2-E). ⑤ 4a-3a 는 4a-2 뒤 · fin 출처에 `CLAUDE.md` 절(R2-F·G). 공유 자원 사용처는 §0-5 한 곳에 전수로.

### 3-4. U1 권고 재판단 — G7 유지 (제약을 넣은 형태)

감사가 G7 의 비용을 올렸다. 다시 비교한다.

| 비교 | G7 | G1′ | G3′ | G6 |
|---|---|---|---|---|
| 구조 4파일 회귀 위험(두 앱 배포 깨짐) | **없음** | 있음 | 없음 | 있음(fin 역할 목록 · C5) |
| C1·C5 env 일치 규칙 | 지켜야 함 | 자동 충족(`deploy.sh` 가 띄움) | 지켜야 함 | 자동 충족 |
| 공용 forced command 변경 | 나중 · 선택 | 필수 | 없음 | 없음 |
| 갱신 비용 | 사용자 실행 → 나중 자동 | 자동 | 매번 사용자 | 자동(fin 과 함께) |
| 롤백 독립 | 예 | 예 | 예 | **아니오** |

**G7 유지.** 이유: G7 이 새로 지는 위험(env 규칙 · 접두 · 락 fd)은 **통합 층 배포 스크립트의 기동 시점 가드와 시험으로 기계적으로 막을 수 있는** 종류다. 위반 결과는 아래 표대로 경우가 갈린다 — 일부는 **바꾼 뒤** 멈추므로(C5 rc 4) "C1 이 받아 준다" 고 기대하지 않고 **기동 시점에서 막는다**(G-R1·G-R2 를 스크립트가 거부). G1′·G6 이 지는 위험(구조 4파일 회귀)은 두 앱 배포 로직 자체를 바꾸는 것이라 시험 6 갱신으로도 다 덮이지 않는다. 자동 배포 단계는 공용 forced command 를 바꾸므로 **처음에는 넣지 않고**, 수동 실행이 몇 회 판정 양식으로 통과한 뒤 별 PR(4b-5)로 올린다 — 그 PR 은 효력이 다음 Release 부터라는 점(AU B-8)까지 런북에 적는다.
*"G7 은 그 위험을 0 으로 둔다"*(r1)는 *"G1′ 보다 작다 — 구조 4파일 무변경 · 공용 진입 1단계(나중)와 env 일치 규칙만 남는다"* 로 고친다.

### 3-5. 상주 프로세스와 배포 락 (A-3)

상주 통합 층은 **질문 동안** 배포 락을 쥐지 않는다 — 쥐면 그 사이 자동 배포가 rc 1 로 실패한다(N21 · S1). 질문 시작 때 `flock -n` 자식으로 **잠깐 잡았다 바로 놓아** 시험한다(배타 락을 잡지 않고 시험하는 방법은 없다 · 공유 락 `-s` 도 배타 요청과 충돌한다 · Node 코어에 flock 이 없어 셸 `flock` 자식 · 선례 `run-x1.sh`). 잡혀 있으면 "배포 중" 으로 답한다. 남는 겹침은 둘이다: ① **그 몇 ms 와 겹친 배포는 `take_lock` 에서 rc 1**(드묾 — 하루 질문 수 P1 · Actions 재실행) ② **시험 직후 시작한 배포와는 질문 동안 겹칠 수 있다**(R-13 — 모델은 도구 오류를 받는다 · 질문 지연 [N3] 동안). 창을 없애려면 배포 쪽이 기다리게(`flock -w`) 바꿔야 하고 그것은 두 앱 배포 경로 변경이다 — **4b 에서는 하지 않는다.** 되돌리기: 코드 **중간**.

**왜 허용 키를 지금 나누나.** 공유 목록에 사람을 더하면 **fin 봇(쓰기 `!ai`)과 fit 봇 접근도 함께 열린다.** 통합 층만 확장할 수 있어야 "확장 가능하게" 가 성립한다. 전용 키는 정규식 3 변경을 부르므로(§0-5 S2 · Q138) 키를 처음 만드는 4b-2 에 넣는다 — 나중에 넣으면 같은 변경 + 운영 중 키 이전이다.
**주의:** 원장이 단일 사용자이므로 통합 층 허용 사용자를 늘리는 순간 **그 사용자는 같은 재무·건강 데이터를 본다.** 다중 사용자 기능을 켜는 결정은 데이터 분리와 함께여야 한다 — 키 자리는 그 결정을 싸게 만들 뿐 대신하지 않는다.

## 12. 감사가 반증해 볼 주장 (3회차용 · 싸다고 한 곳 위주)

2회차 확인으로 닫힌 것(AU2 C-1~C-8): `NOTIFY_AI_FALLBACK_*` 정규식 0 · 플랫폼 env 재읽기 · `prompts/get` 과 sid 가드·세션 수명 · `pm2 save`/resurrect 의 env 유지 · `release-inplace.sh` 가 `pleiades-*` 전체를 보는 곳은 `env_same` 하나 · 4b-5 효력 시점 · 릴리즈 종류 · G6 cwd·DB.

1. **§0-5 S1~S4 가 전수다** — 표마다 적은 grep 명령으로 빠진 사용처가 없는가(특히 S1 `discord-switch.sh` 행: 주석은 같은 락이라 하나 코드 0 · S2 `docs/runbooks` 밖 문서).
2. **위반 결과 표(§3-4)가 `release-inplace.sh` 동작과 일치한다** — 특히 G-R2 위반 · cwd 체크아웃 밖 = C1 rc 1 · C5 rc 4 뒤 `--retry` 만으로 회복(원인 제거 뒤) · R-8 불필요라는 주장.
3. **G-R3 fd 닫기 시험이 정적 검사로 충분하다** — 통합 층 배포 스크립트가 부르는 npm·node 가 pm2 를 간접으로 띄우는 경로가 없는가.
4. **G-R1 기동 시점 거부가 배포 도중 재기동을 막는다** — 스크립트 경유 재기동은 G-R3 락으로 앱 배포와 직렬화되므로 C1 뒤 env 변경이 생기지 않는다는 주장(직접 `pm2 restart` 는 런북 금지로만 막힌다 — 잔여 위험).
5. **4a-3a 가 fin advisor 답을 바꾸지 않는다** — 조건(prompt 는 읽기 경로에만) 아래에서 fin MCP 의 다른 변경(지식 파일 읽기 실패 로그 등)이 전체 경로 도구에 닿지 않는가.
6. **Q138 필수 변경(정규식 3 · 시험 2 · 문서 3)** — S2 표 밖 소비자.
7. **[D2] 근거의 P6** — N6 이 부풀었으면 여유는 2배보다 크고, 통합 층은 두 도메인 지식(N10)을 싣는다 — 앱 대화보다 비쌀 수 있다.
8. **4b-1 등록 N24 = 필수 9 + 선택 1** — `apps/*` 를 열거하는 다른 곳(release 노트 생성 · `tools/import` · `.claude/hooks`)이 더 있는가.
