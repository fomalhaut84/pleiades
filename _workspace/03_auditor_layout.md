## 1. 주장 "`mv` 한 번이면 끝" — **정정**

02 초안 §4 옵션 1 은 A-mv 의 소요를 *"이동 수 초 + 참조 갱신"* 으로 적었다.
감사는 **절반을 확인하고 절반을 뒤집었다.**

### 1-1. 확인된 부분 — 재설치·재생성은 **불필요**

`npm ci` / `prisma generate` / `npm run build` 를 이동 후에 다시 돌려야 한다는 통념은
**실증으로 기각**됐다.

| 검사 대상 | 실측 | 판정 |
|---|---|---|
| `node_modules` 심링크의 절대경로 | myFinance **0 / 45**, myFitness **0 / 39** | 전부 상대 심링크 — 이동 무관 |
| lockfile 안의 절대경로 | **0건** | 무관 |
| `.git/hooks` 의 절대경로 | **0건** | 무관 |
| Prisma 쿼리 엔진 바이너리의 경로 임베드 | **0건** | 무관 |
| `.prisma/client/index.js:525,539` 등의 절대경로 | 존재 | **inert metadata** — 런타임 해석은 `__dirname` 기준 |

`.prisma/client` 의 절대경로는 **실기동으로 무해함을 확인**했다: APFS 복제본을 새 경로에서
실제로 띄웠고, **DB 연결 단계에서만** 실패했다(경로 문제가 아니라 `.env`/DB 문제).
경로 해석 단계는 통과했다.

### 1-2. 뒤집힌 부분 — `.next/cache` 는 **절대경로로 키잉된다**

| | myFinance | myFitness | 합 |
|---|---|---|---|
| 절대경로를 담은 `.next/cache` 파일 | **160** | **9** | 169 |
| 단일 `index.pack` 안의 **distinct** 절대경로 | **1,144개** | — | — |
| 관련 캐시 용량 | — | — | **1.35 GB** |

→ 이동하면 **첫 빌드 1회가 콜드**가 된다. 되돌릴 때 **한 번 더** 콜드.
   앱이 깨지지는 않지만 *"이동 수 초"* 라는 서술은 성립하지 않는다.

### 1-3. **방법론 경고 — 1차 스캔 2건이 모두 0건 오탐이었다**

`01_surveyor_layout.md` M3 과 감사 자신의 1차 스캔이 **둘 다 `.next/cache` 를 0건으로 보고**했다.
원인은 하나다: **`grep -r` 이 이 파일들을 binary 로 판정해 건너뛴다.**

```bash
# 이 저장소의 절대경로 측정 표준 플래그
grep -rn --binary-files=text -- "/Users/sagan/workspace" <path>
```

**판정: `--binary-files=text` 를 이 저장소의 절대경로 측정 표준 플래그로 박는다.**
그리고 **`docs/research/measured-facts.md` 의 기존 grep 기반 "0건" 결론들이 같은 결함을
가질 수 있다** — 특히 M3 의 "myFitness 소스·설정 전체 0건", M4 의 "`rsync`/`scp` 0 / 0".
재검증 전까지 그 0 들은 **"텍스트 파일 범위에서 0건"** 으로 읽어야 한다.

## 2. 주장 "`~/.claude/projects/` rename 하면 보존" — **정정 (부분 작동)**

02 초안 §3-1 완화안 (a). 감사 판정: **rename 자체는 작동한다. 그러나 그것만으로는 부족하다.**

### 2-1. 작동이 실증된 것

디렉터리 rename 후 ① memory 주입 ② `--resume` 로 세션 회수 ③ 신규 세션이 새 키에 기록됨
— **셋 다 확인**. 즉 완화안 (a) 는 `~/.claude/projects/` **한 곳에 대해서는** 유효하다.

### 2-2. 그러나 경로 키잉 저장소는 **3개**다

| # | 저장소 | 담긴 것 | rename 으로 해결되나 |
|---|---|---|---|
| ① | `~/.claude/projects/<slug>/` | 세션 `.jsonl` · `memory/` | **예** (실증) |
| ② | `~/.claude.json` 의 `projects["<절대경로>"]` | 신뢰 대화상자 · `codex-cli` MCP 등록 · `lastSessionId` | **아니오** — 키가 절대경로 문자열 |
| ③ | `~/.claude/history.jsonl` | 프롬프트 **2,046건** | **아니오** |

02 초안은 ①만 보고 "완화안 (a) 로 보존"이라 썼다. ②·③ 은 초안에 **등장하지 않는다.**

### 2-3. 슬러그 규칙도 문서가 틀렸다

| | 기존 기록 | 감사 실측 (CLI **v2.1.260**) |
|---|---|---|
| 치환 규칙 | `/` → `-`, **`_` 는 보존** (`-Users-sagan-workspace-knou_python`) | **`/`·`_`·`.` → `-`** |
| 안정성 | 규칙으로 서술 | **CLI 버전 의존** |

`knou_python` 키에 `_` 가 남아 있는 것은 **과거 CLI 버전이 만든 키**이기 때문이다.
→ 슬러그를 손으로 계산해 rename 하는 절차는 **CLI 업그레이드에 깨진다.**

### 2-4. `autoMemoryDirectory` — (a) 의 대안이 아니다

실재하는 설정이다. 그러나 **세션 키는 못 옮길 가능성이 높다.**
02 초안 §3-1 (b) 가 이미 "memory 만, 기껏해야 부분 완화"라 적은 것과 같은 결론이지만,
감사도 **실증하지 못했다** → **미확인으로 남긴다.**

### 2-5. **최종 채택안(worktree)에서는 이 비용이 전부 0 이다**

worktree 는 `~/workspace/myFinance` · `~/workspace/myFitness` **원본 경로를 그대로 유지**한다.
따라서 ①②③ 어느 것도 키가 바뀌지 않는다. **§2 전체가 A-mv 에만 걸리는 비용이다.**

## 3. 주장 "`.gitignore` 에 `repos/` 한 줄이면 충분" — **정정**

02 초안 §2-2 비용 4 · §5 조건 C2 · M5.

| 검사 | 실측 | 판정 |
|---|---|---|
| ignore 상태에서 `git add repos/inner` | 차단 | 초안대로 |
| ignore 상태에서 **`git add -f repos/inner`** | **뚫린다 — gitlink 생성** | **초안 반증** |
| `git clean -fdx` | 중첩 저장소를 **보호** | 안전 |
| **`git clean -ffdx`** | **`repos/` 를 통째로 삭제** | **초안 미기재 위험** |

→ `.gitignore` 한 줄은 **사고를 막는 장치가 아니라 기본값을 바꾸는 장치**다.
   `-f` 를 두 번 치면 뚫리고, `clean -ffdx` 는 지운다.

**단, worktree 채택으로 이 항목의 판돈이 줄었다.** `repos/` 가 삭제돼도 **원본 체크아웃이 남으므로
편도가 아니다** — `git worktree add` 재실행 + gitignored 사본 재복사로 복구된다.
A-mv 였다면 `clean -ffdx` 한 번이 유일본 삭제였다.

## 5. 감사 이후 오케스트레이터가 따로 실측한 것 (출처 구분)

감사 판정이 아니다. **초안에 없던 신규 실측**이며 채택안 선택에 직접 쓰였다.

### 5-1. §3 의 Grep 정정에 대한 **완화** — 차단이 아니라 루트 traversal 제외

감사는 "`repos/` 를 ignore 하면 Grep 도구가 못 본다"고 했다. **경로를 명시하면 찾는다.**

| 검색 | 결과 |
|---|---|
| 루트 검색 (경로 미지정) | ❌ 미검색 |
| `path: repos/inner` | ✅ `FOUND:repos/inner/src.txt` |
| `path: repos/` | ✅ 검색됨 |

→ **규칙 한 줄로 처리된다**: *"`repos/` 하위를 검색할 때는 `path` 를 명시한다."*

### 5-2. **중첩 `.claude/` 는 로드되지 않는다** (신규 · 결정적)

| 배치 | `.claude/skills` | `.claude/agents` |
|---|---|---|
| 하위 디렉터리 (`repos/*/.claude/`) — gitignore **유무와 무관** | **미발견** | **미발견** |
| **`--add-dir` 로 붙인 경우** | **발견** | **발견** |

→ 02 초안 §7 의 **L4 가 "안 됨"으로 확정**됐다.
   **하네스 통합(002 단계 2)은 이 배치에서 선택이 아니라 선결 조건이다.**
   순서 변경은 `CLAUDE.md` 핵심 전제 1(축 A·B 독립)이 허용한다.
