## 0. 한 줄 요약

**D-2 는 "fit 핸들러를 Discord 에 한 벌 더 다는" 일이 아니라, chat 이 grammY 와 다르게 동작하는 네 곳(명령 매칭 · 직렬화 · 채널 구분 · 4014)을 먼저 맞추고 그 위에 판단을 분리한 fit 핸들러를 얹는 일이다.**
그대로 붙이면 ① `sleep 어땠어?` 가 수면 명령으로 가고(N24) ② 같은 채널 메시지가 동시에 처리돼 편집 대기 상태가 꼬이고(N25) ③ **알림 채널 메시지까지 명령으로 받고**(W4) ④ 포털 토글을 잊으면 4014 로 `auto_adjust` 버튼까지 끊긴다(N13).
켜고 끄는 수단은 **대화 채널 ID 키 하나**(`DISCORD_CHANNEL_ID_FITNESS_CHAT` · 선택)로 둔다 — 비어 있으면 D-1 동작(intents 0 · 버튼만) 그대로라 **릴리즈 자체는 서버 조치가 없고**, 켜기는 릴리즈 뒤 별도 서버 단계(스크립트 + 판정 양식)다. 키를 비우면 **재시작 없이 다음 메시지부터** Discord 수신이 멈춘다(W2·W3).
권고 순서 **PR-1 chat 확장 → PR-2 fit 판단 분리·상태 키(텔레그램 동작 무변경) → PR-3 fit Discord 수신 + 켜기 스크립트 → D-2 릴리즈(minor) → 켜기(사용자 · 서버)**.

### R. 명령 매칭 (Δ1 · 쟁점 1)

**문제:** fit 명령 이름은 영어 단어(`start·help·today·run·sleep·weight·sync·report·ai·reset`)다. 앞 `/` 를 선택으로 두면 `sleep 어땠어?` → 수면 명령 · 편집 대기 중 설명 `run 후 바나나` → 러닝 명령(N24 · [S] C4). 텔레그램에서는 둘 다 자유 텍스트였다.

| | 안 | 얻는 것 | 잃는 것 · 위험 | 되돌리기 |
|---|---|---|---|---|
| R1 | 그대로(앞 `/` 선택) | 변경 0 | 자연어·편집 입력 오인 — §4-2 "자유 텍스트 4 분기 그대로"(2-1) 위반 | — (기각) |
| R2 | 앱 우회 — `command()` 를 쓰지 않고 `hears(/^\/(today)(?:\s+([\s\S]*))?$/i)` 같은 정규식으로 등록 | chat 무변경 | 앱이 라우터 계약을 우회 — fin(D-3)도 같은 우회를 반복(C-8 "한 번") · 첫 단어 명령 기능이 쓰이지 않는 채 남는다 | **즉시** |
| ★ **R3 · 권고** | **chat 라우터: 명령의 앞 `/` 를 등록 단위로 정한다** — `command(names, h, { slash?: 'required' \| 'optional' })` · **기본 `required`**(텔레그램·grammY 와 같다) · `optional` 은 fin 의 접두 없는 한글 명령(L2 "둘 다 17")처럼 앱이 명시할 때만 | 오인 위험이 기본값에서 사라진다 · fin 이 D-3 에서 같은 문제를 다시 풀지 않는다 · **소비자 0 이라 기본값 변경이 공짜**(W1) | 공개 계약 옵션 1개 · 기존 `today`≡`/today` 테스트 갱신 | 옵션 삭제(**즉시** · 소비자 생기면 **중간**) |
