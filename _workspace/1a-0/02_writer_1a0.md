| 제약 | 근거 | 귀결 |
|---|---|---|
| **git 의존성은 클론 루트의 `package.json` 만 읽는다** | 케이스 A `ENOENT`(EXIT 254) · 서브디렉터리 문법 0건 ([B] M1) | **루트에 `package.json` 이 있어야 한다** — 또는 **루트가 곧 패키지인 ref 를 따로 만든다**(ALT-a) 또는 **git 을 안 쓴다**(ALT-b) |

> `npm ci`·`require`·`tsc --noEmit`(fin·fit 옵션 사본) 전부 통과했다 ([C] §1-3).

**여전히 유효한 제약 2개:** `workspaces` 는 소비자 설치에서 전개되지 않는다(케이스 C, [B] M1) · `files` 는 `prepare` 산출물을 담는다(케이스 B, [B] M1).

## 1-6. Q28 — 형태와 **표기 유지 절차** (감사 ⑤)

**Q28 의 원래 물음은 소멸한다** — 세 형태 전부 자격 불필요, 실제 전송은 셋 다 https ([B] M2 · [C] §5-1 재현).

| 형태 | 자격 | 전송 | `package.json` (설치 명령 경로) | lockfile `resolved` | `integrity` |
|---|---|---|---|---|---|
| `github:…#<tag>` | 불필요 | https | `github:…` | `git+ssh://…` | **없음** |
| **`git+https://…#<tag>` (권고 표기)** | 불필요 | https | **`github:…` 로 정규화됨** | `git+ssh://…` | **없음** |
| `git+ssh://…#<tag>` | 불필요 | https (ssh 0회) | `github:…` 로 정규화됨 | `git+ssh://…` | **없음** |

> ⚠ **1회차 권고 근거 ①(*"표기가 실제 전송과 일치한다"*)은 그대로는 성립하지 않는다.**
> `npm install "git+https://…"` 는 **`package.json` 문자열까지 `github:` 단축형으로 정규화**한다([C] §5-2).
> 그리고 **`integrity` 는 git 의존성 공통으로 없다** — 무결성 해시는 **타르볼 배포(ALT-b)에만** 붙는다.

**절차로 승격한다 (1a-3 집행 지시 항목):**

| # | 절차 | 되돌리기 |
|---|---|---|
| 1 | 의존성은 **`package.json` 직접 편집**으로 추가한다 (`"@pleiades/notify": "git+https://github.com/fomalhaut84/pleiades.git#<tag>"`). **ALT-d 를 택하면 이 편집이 필수다** — 위치 인자 설치는 `pleiades` 로 들어간다 | **즉시** (1줄) |
| 2 | 편집 후 `npm install` 을 돌리고 **문자열이 `github:` 로 바뀌지 않았는지 확인**한다 (직접 편집분은 유지됨 — 실측) | **즉시** |
| 3 | 그 뒤 `npm ci` 재현성을 확인한다 (직접 편집 + `npm ci` 조합 실측: `added 1 package in 532ms`, `package.json` 불변) | **즉시** |

**대안:** 정규화를 그냥 수용하고 **`github:fomalhaut84/pleiades#<tag>` 를 정본 표기로** 삼는다 — 절차 항목이 사라지고(되돌리기 즉시),

## 3-4. 권고 (⑧·⑨ 반영 — **역할을 셋으로 나눈다**)

> **γ 를 개발 루프로 · β2 를 서버 도달 검증으로 · `send.ts` 의 위험 분기는 패키지 단위 테스트로.**
> α 는 채택하지 않는다. β1 은 필요 없다. δ 는 보류.

| 판단 | 근거 |
|---|---|
| **α 배제 — 근거 교체 (감사 ⑧)** | 1회차 근거(*"폴백은 L3 를 타지 않는다"*)는 **틀렸다.** 폴백 문구도 **같은 `sendToAll` 을 탄다**(`scheduler.ts` catch). 정확한 근거: **폴백은 L3 의 위험 분기를 밟지 못한다** — `send.ts:9 MAX_MSG=4096` · `:34 truncate()` · `:44 태그 제거 plain` · `:57 HTML parse 실패 → plain 재전송` 은 **긴 HTML 본문에서만** 발동하고, 폴백 문구(`❌ … 생성 실패`)는 태그가 없고 4096 에 한참 못 미친다([C] §8). **그 두 분기가 곧 003 Q10 의 대상**이므로 α 에서는 **1a 가 바꾸는 바로 그 동작을 fit 에서 볼 수 없다** |
| **γ 우선 (유지)** | 선행 조건이 로컬에서 충족 가능(`.env`·`node_modules`·Postgres 5432 리슨, [A] M4). 서버 승인 불필요. **Q23 을 전제 원문 그대로 푸는 유일한 옵션** |
| **β2 를 서버 도달 검증으로 (한계 명시)** | γ 는 서버 환경(node·https·pm2·`prepare`)을 재현하지 않는다 — **Q45 와 배포 경로는 서버에서만 검증된다.** **다만 β2 가 증명하는 것은 "메시지가 도달한다"까지다** — fit 본문은 `spawn(CLAUDE_BIN)` + MCP 4301 산물이라 **빈 DB 에서 어떤 본문이 나오는지 미측정(RM-4)** 이고, 나오더라도 길이·HTML 구조가 실데이터와 달라 **절단·plain 분기 커버는 보장되지 않는다**([C] §9). **그리고 β2 가 배포 경로(`prepare`·Q45)를 검증하는 것은 병행 인스턴스가 git dep 을 실제로 `npm ci` 한 뒤부터다 = 1a-3 이후**([C] §2-5 ⑦) — 그 전의 β2 는 **텔레그램 도달만** 본다. 따라서 **β2 의 서버 승인 게이트는 1a-3 과 함께 소비하는 편이 싸다** |
| **위험 분기는 단위 테스트로 (신설)** | 위 한계의 해법은 β1 이 아니다. **4096 절단·HTML parse 실패 폴백은 패키지 자체 테스트(1a-1 vitest)의 대상**이고, 003 §5-1 이 이미 *"테스트 범위는 **패키지 코드로만** 한정"* 이라고 적었다. **검증 부담을 인스턴스에서 테스트로 옮기면 β1 이 불필요해진다.** **커버 범위는 분기 로직까지다** — `isHtmlParseError` 가 **메시지 정규식**(`/can't parse entities|Bad Request:.*entit/i`, `bot/utils/error.ts`)이라 mock 으로 **결정적으로** 재현된다([C] §2-5 ⑥). **잔여 둘은 명시한다:** ① 텔레그램이 실제로 그 문구를 반환하는지(정규식↔실 API 결합) ② 새 L3 가 만든 HTML 이 실제로 parse 에러를 유발하는지. **어떤 인스턴스 검증도 이 잔여에 '한 번 맞았다' 이상을 주지 못하므로 β1 배제는 유지된다.** fit 저장소에는 현재 테스트 파일이 **0개**라 1a-1 이 처음부터 쓴다 |
| **β1 배제 (1회차에서 강화)** | 1회차는 *"β2 가 부족하면 β1"* 이라고 열어 뒀다. **닫는다** — β1 의 유일한 이득(실데이터 본문)은 위 단위 테스트로 대체되고, β1 은 **되돌려도 남는 것**(사본 존재 기간의 노출)이 있는 유일한 옵션이다. 게다가 **β2 에서 `GARMIN_*` 에 실값을 넣으면 `syncAll` 이 사본 DB 를 실데이터로 채워 β2 가 β1 이 된다**([C] §9) — 그래서 조건 8 에 `GARMIN_*` 을 넣었다 |
| **δ 보류 (유지)** | cron off 를 env 화해도 **DB 쓰기는 남는다**(조건 2 대체 불가). β 를 택하면 필요가 사라진다 |

**남는 위험 1건:** fit 웹은 **어느 옵션에서도** 부팅 시 `sweepOrphanedJobs()` 를 실행한다. `DATABASE_URL` 을 잘못 넣는 순간
**실서비스 job 이 `failed` 로 마킹된다.** → 조건 2 의 검증을 **기동 전 절차**(URL 이 `_int` 로 끝나는지)로 못 박는다.
