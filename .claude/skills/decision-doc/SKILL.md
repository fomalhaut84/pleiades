# decision-doc — 방향 문서 형식

pleiades 의 산출물은 코드가 아니라 결정과 근거다. 이 저장소 문서의 정체성은 하나의 형식에 있다:

> **모든 선택지에 되돌리기 비용을 함께 적는다.**

그래야 "지금 안 해도 되는 것"과 "지금 안 하면 비싸지는 것"이 구분된다. 이 한 줄이 빠지면
문서는 그냥 아이디어 목록이 되고, 무엇부터 할지 판단할 근거가 사라진다.

## 문서 골격

```markdown
# NNN — <제목>

작성 YYYY-MM-DD · 상태 <기획 완료 / 방향 확정 / 실행 중>
읽기용 아티팩트: <URL>
(**정본은 이 파일이다.** 아티팩트는 사본)

## 1. 무엇이 바뀌었나     ← 개정일 때만
## 2. 확정된 답
## 3. 실측 근거
## 4. 경로
## 5. 판단이 바뀐 것       ← 개정일 때만
## 6. 남은 미결 질문
## 7. 유효기간
```

## 각 절의 규율

### 1. 무엇이 바뀌었나 (개정 문서)

**결론이 바뀐 이유는 거의 항상 전제가 바뀐 것이다.** 그 전제를 명시한다.

이전 문서를 인용하고 → 어떤 입력이 그 전제를 깼는지 → 그래서 무엇이 달라지는지.
사용자 발언이 근거면 **원문을 그대로 인용**하고 날짜를 붙인다. 요약하면 나중에 재해석의 여지가 생긴다.

### 2. 확정된 답

| | 질문 | 답 | 근거 |
|---|---|---|---|
| Q1 | ... | ... | 사용자, YYYY-MM-DD |

답이 새 질문을 낳으면 그 질문도 여기서 번호를 받는다 (Q5, Q6…). **왜 그 질문이 지금 필요한지**를 함께 적는다.

### 3. 실측 근거

숫자는 `docs/research/measured-facts.md` 에서 **인용만** 한다. 여기서 새로 측정하거나 추정하지 않는다.
필요한 값이 없으면 `repo-surveyor` 에게 측정을 요청하고 기다린다.

### 4. 경로 — 옵션 사다리와 단계 표

옵션에는 되돌리기 비용을 등급 + 구체적 행위로 적는다:

| 등급 | 의미 | 표기 예 |
|---|---|---|
| 즉시 | 설정 삭제, 플래그 제거 | "설정 키 삭제" |
| 중간 | 며칠 작업 | "각 저장소로 재인라인, 며칠" |
| 높음 | 이력이 얽힘 | "git 이력이 얽힌다. filter-repo 로 분리 가능하나 실질적 편도" |
| 사실상 불가 | 데이터 마이그레이션 역방향 | — |

단계 표는 이 4열을 유지한다:

| 단계 | 내용 | 이전 문서 대비 | 되돌리기 |
|---|---|---|---|

**각 단계는 그 지점에서 멈춰도 손해가 없어야 한다.** 단계마다 "여기서 멈춰도 무엇이 남는지"를 적는다.
남는 게 없는 단계는 단계가 아니라 중간 작업이므로 앞뒤와 합친다.

### 6. 남은 미결 질문

| | 질문 | 무엇을 가르는가 | 우선 |
|---|---|---|---|

**"무엇을 가르는가"가 없는 질문은 적지 않는다.** 답이 아무것도 바꾸지 않으면 물어볼 이유가 없다.
우선순위는 "지금 답해야 다음이 풀리는가"로 정한다. 나중에 답해도 되는 질문을 위로 올리지 않는다.

### 7. 유효기간

이 문서를 **언제 다시 열어야 하는지** 적는다. 조건으로 쓴다 ("도메인 #3 을 붙일 때"),
날짜로 쓰지 않는다. 조건이 없으면 문서는 영원히 유효한 척하다가 조용히 stale 해진다.

## 개정 규약

**이전 문서를 폐기하지 않는다.** 001 을 002 가 대체할 때도 001 은 분석 근거로 남는다.
개정본은 무엇을 대체하고 무엇을 남기는지 첫 문단에서 밝힌다:

> 001 을 폐기하지 않는다. 001 의 축 A/B 분해와 실측은 그대로 유효하고, **권고 경로와 종착지만 바뀐다.**

`CLAUDE.md` 의 문서 지도와 상태 표기도 함께 갱신한다. 이걸 빼먹으면 다음 세션이 옛 문서를 정본으로 읽는다.

## 정정 규약

기록이 틀렸을 때 **지우지 않는다.** 지우면 왜 틀렸는지가 사라지고, 같은 실수를 반복한다.

```markdown
> **정정 (YYYY-MM-DD 재측정).** <이전 기록>은 틀렸다.
> 실제로는 <실측 결과>. 상세는 <참조 절>.
```

정정이 로드맵을 바꿀 만하면 별도 "발견 N" 으로 승격하고 아티팩트에도 반영한다.

## 아티팩트 발행

아티팩트는 사본이고 **정본은 로컬 마크다운**이다. HTML 소스는 `docs/artifacts/` 에 두어 버전 관리한다 —
그래야 다음 세션에서 같은 URL 로 재발행할 수 있다.

발행 전 **반드시** 현재 버전을 읽는다. 읽지 않은 아티팩트에 대한 발행은 거부된다:

```
1. Artifact(action="read", url=<기존 URL>)
2. 결과가 가리키는 저장 파일을 1행부터 끝까지 전부 Read
   (1행은 발행 시 자동 주입되는 런타임이라 내용은 없지만 읽어야 열람으로 인정된다)
3. 내용 병합·개정 → docs/artifacts/<name>.html
4. Artifact(file_path=..., url=<기존 URL>, label="<개정 요약>")
```

- **제목(`<title>`)은 재발행 때 바꾸지 않는다.** 사용자가 탭·갤러리에서 찾는 이름이다
- `favicon` 은 재발행 시 생략한다 (기존 아이콘 유지)
- `force` 는 사용자 명시 승인 없이 쓰지 않는다

## 인계 노트

세션 종료 시에는 `pleiades-handoff` 스킬을 쓴다.

## 하지 않는 것

- **숫자를 직접 추정하지 않는다.** `measured-facts.md` 에 없으면 측정을 요청한다
- 감사(`reversibility-audit`) 전 문서를 정본으로 취급하지 않는다. 그전까지는 `_workspace/` 의 초안이다
- 대상 두 저장소에 쓰지 않는다. 집행은 `dual-repo-operator` 의 일이다
