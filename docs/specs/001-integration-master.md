## 1. 문제 정의

두 프로젝트는 이미 같은 아키텍처의 두 갈래다. 그래서 질문은 "통합할까?"가 아니라
**"어디까지 합치고 어디서 멈출까?"** 다.

사용자 요구 두 가지:
1. 두 프로젝트를 통합해서 키우고 싶다
2. 각각 따로 쓰던 Claude Code CLI 를 통합하고 세션 연속성을 유지하고 싶다

전제: **실행 여부는 미정.** 따라서 각 단계는 그 지점에서 멈춰도 손해가 없어야 한다.

## 2. 핵심 발견

### 발견 1 — "통합"은 두 개의 독립 축이다

| | 축 A · 하네스·세션 | 축 B · 코드·제품 |
|---|---|---|
| 다루는 것 | 스킬, 에이전트, 규칙, 메모리, 세션 | 저장소, 패키지, 런타임, DB |
| 코드 변경 | 없음 | 있음 |
| 되돌리기 | 설정 삭제 | 저장소 수술 |

**따로 결정할 수 있다.** 축 A 는 축 B 없이도 이득이 나고, 축 B 는 축 A 가 먼저 있으면 싸진다.
여기서 순서가 정해진다.

### 발견 2 — 하네스는 이미 쌍둥이인데 이름만 다르게 두 번 만들어졌다

역할 대조표는 `../research/measured-facts.md` 참조. 요점 두 가지:

- 같은 역할이 다른 이름으로 존재 (`session-resume` / `session-primer` 등)
- **각자에게만 있는 스킬**이 있다 — myFinance 의 `project-verify`·`project-spec-writer`,
  myFitness 의 `ops-diagnose`·`prisma-drift-fix`·`orphan-check`.
  합집합만 취해도 양쪽이 즉시 좋아진다.

코드 쪽도 같은 모양이다. `src/mcp/session-utils.ts` 는 양쪽 다 44줄인데 22줄이 다르다 —
같은 파일이 복사된 뒤 각자 흘러간 것.

### 발견 3 — AI 어드바이저 통합은 코드 통합 없이 지금도 된다

두 MCP 서버가 이미 같은 서버에서 로컬 HTTP 로 상주 중이다 (`:4210`, `:4301`).
`mcp-config.json` 한 파일에 두 항목을 함께 넣으면
**하나의 Claude 세션이 재무와 건강 데이터를 동시에 본다.**

> 이것이 "키운다"의 실체다. 저장소를 합쳐야 얻는 게 아니다.
> "이번 달 야근이 늘었는데 수면·러닝 부하와 외식비가 같이 어떻게 움직였나" 같은 질문이
> 두 MCP 를 한 세션에 물리는 순간 가능해진다. 되돌리기는 JSON 두 줄 삭제.

## 3. 축 A — 하네스·세션 통합

메커니즘 상세는 `../research/claude-code-mechanisms.md`.

### A0 · 현상 유지 — *현재*
프로젝트별로 따로 띄우고 하네스도 따로 관리.
**대가**: 스킬 개선이 한쪽에만 반영. `ops-diagnose`·`project-verify` 가 서로 없는 채로 몇 달째.

### A1 · 공유 하네스 플러그인 — *되돌리기: 즉시*
공통 스킬·에이전트를 플러그인 하나로 묶어 두 프로젝트에서 로컬 마켓플레이스로 설치.
프로젝트 고유 규칙(세금 로직, Garmin 필드 casing)은 각자 `.claude/` 에 남긴다.

- **얻는 것**: 스킬 합집합. 한쪽 개선이 양쪽 반영. 이름 통일
- **되돌리기**: `/plugin uninstall`. 원본을 지우지 않고 병행 시작하면 손실 0
- **선결**: 역할별 정본 선택 (더 성숙한 쪽 채택)
- **주의**: 동명 에이전트는 로컬이 플러그인을 덮어쓴다. 원본 삭제 필요

### A2 · 메모리 공유 + 통합 어드바이저 — *되돌리기: 즉시*
두 프로젝트의 `autoMemoryDirectory` 를 같은 경로로. 동시에 `mcp-config.json` 병합(발견 3).

- **얻는 것**: 세션 연속성. 도메인 교차 질문이 가능한 어드바이저
- **되돌리기**: 설정 키 삭제 + 메모리 파일 분리 (평범한 markdown)
- **선결**: myFinance `MEMORY.md` 압축 — 현재 126줄, 한도 200줄, 합산 142줄로 여유 58줄뿐
- **리스크**: 메모리 오염 — 재무 컨텍스트가 피트니스 세션에 섞임. 인덱스 규율이 곧 비용

### A3 · 단일 워크스페이스 세션 — *되돌리기: 낮음*
`~/workspace` 상위에서 띄우고 `--add-dir` 로 두 저장소를 붙인다.

- **주의**: 공식 권고는 반대 방향 — 작업이 한 패키지에 국한되면 그 디렉터리에서 시작하라
- **쓸 때**: 공유 패키지 추출처럼 **실제로 두 저장소를 동시에 건드리는 작업**일 때만. 상시 모드 부적합
- **되돌리기**: 플래그 제거. 단 `--add-dir` 는 `--resume` 시 복원 안 됨

## 4. 축 B — 코드·제품 통합

### B0 · 저장소 분리 유지 — *현재*
**대가**: 공용 모듈이 계속 갈라진다. `#180` MCP HTTP 승격이 myFinance → myFitness 로
손으로 옮겨진 전례가 이미 있다.

### B1 · 공유 패키지만 추출 — *되돌리기: 중간*
저장소는 둘로 두고 진짜 중복만 별도 패키지로. 후보는 특정되어 있다:
MCP 서버 뼈대(`logger`, `session-utils`, HTTP transport), `claude -p` 어드바이저 래퍼,
텔레그램 포맷·에러 유틸, KST 날짜 유틸.
배포는 npm 레지스트리 없이 git 의존성이나 `file:` 링크로 충분하다 (1인 프로젝트).

- **얻는 것**: 버그 픽스 1회로 양쪽 반영. 드리프트 정지
- **되돌리기**: 각 저장소로 재인라인. 며칠 작업이지 재앙은 아님
- **선결 1**: Next 15 → 16 정렬. 공유 패키지가 서로 다른 major 를 상대하면 이득이 사라진다
- **선결 2**: myFitness 테스트 도입. 없으면 공유 코드 변경이 검증 없이 실서비스로 간다

### B2 · 모노레포 — *되돌리기: 높음*
npm workspaces 로 `apps/finance`, `apps/fitness`, `packages/*`.
루트 CLAUDE.md 에 공통 규칙, 앱별 CLAUDE.md 에 도메인 규칙 (공식 권고 레이아웃).

- **얻는 것**: 단일 검증 파이프라인, 단일 배포, 원자적 크로스-앱 변경
- **대가**: 릴리즈 격리 상실. 버전 체계가 `v0.16.4` vs `v2.27.2` 로 완전히 달라 태그 정책 재설계 필요
- **되돌리기**: git 이력이 얽힌다. `filter-repo` 로 분리 가능하지만 실질적으로 편도
- **주의**: 루트에서 시작하면 양쪽 CLAUDE.md·스킬이 다 딸려온다. `claudeMdExcludes` + "앱 디렉터리에서 시작" 규율 필수

### B3 · 단일 앱 (생활 대시보드) — *되돌리기: 사실상 불가*
웹 하나, 봇 하나, MCP 하나, DB 하나(Postgres schema 로 도메인 분리).
PM2 프로세스 6개 → 3개. 봇 두 개와 각각 대화하던 것이 하나로.

- **판단**: 통합 이득의 대부분은 이미 A2 와 B1 에서 나온다. B3 가 추가로 주는 건
  **UI 통합과 프로세스 절감**이지 새로운 능력이 아니다
- **비용**: DB 마이그레이션, 봇 토큰·명령 체계 재설계, 알림 라우팅 재설계, UI 병합
- **시점**: 지금 결정할 문제가 아니다. B2 를 6개월 굴려보고 판단해도 늦지 않다

## 6. 권고 경로

앞 단계일수록 값싸고 가역적이다. 다음 단계로 갈지는 그때 다시 판단한다.

### 단계 0 · 통합 어드바이저부터 켠다 — *지금, 반나절*
두 `mcp-config.json` 에 서로의 MCP 항목 추가 → 텔레그램 `/reset`
(기존 `--resume` 세션은 옛 도구 목록을 붙잡고 있다).
코드 통합 없이 교차 도메인 질문이 되는지 **실제로 써 보는 것**이 목적.
**여기서 재미가 없으면 나머지 단계는 할 이유가 없다.**
> 멈춰도: 잃는 것 없음. JSON 두 줄 되돌리면 원상복구.

### 단계 1 · 하네스를 플러그인 하나로 (A1) — *1~2일*
역할별로 더 성숙한 쪽을 정본으로 골라 공유 플러그인 저장소 구성.
원본은 지우지 말고 병행 운영으로 시작.
> 멈춰도: 스킬 합집합은 남는다. 코드는 그대로.

### 단계 2 · 메모리 한 벌로 (A2) — *반나절*
myFinance `MEMORY.md` 압축(완료 마일스톤 기록을 한 줄로) → `autoMemoryDirectory` 동일 경로 지정.
> 여기까지가 "세션 연속성 유지"의 실질적 완성. 코드는 여전히 무변경.

### 단계 3 · Next 16 정렬 + 공유 패키지 (B1) — *1~2주*
myFinance 15 → 16 (PR #58 폐기 후 새로) → MCP 뼈대·어드바이저 래퍼·봇 유틸 추출.
빼기 전에 해당 코드의 테스트를 먼저 붙인다.
**축 A 와 무관하게 독립적으로 가치가 있다.**
> 현실적으로 가장 좋은 종착지일 수 있다.

### 단계 4 · 모노레포 / 단일 앱 (B2·B3) — *B1 을 몇 달 굴려본 뒤*
B1 운영 경험이 "저장소가 둘이라 아프다"를 실제로 보여줄 때만.
> 진입 조건: B1 상태에서 크로스-저장소 변경이 **월 2회 이상** 발생할 때.
