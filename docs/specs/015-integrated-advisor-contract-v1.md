> 대조표 전문(감사 번호 → 반영 위치)은 `_workspace/239/v1/02_writer_v1_r2.md`(r1→r2) · `02_writer_v1_r3.md`(r2→r3) 머리에 있다. 여기는 요지만.

> **r2 → r3 (감사 2회차 · 정정 7 · 직접 반영).** ① `mcp` 새 앱의 앱 쪽 필수는 5(계약 시험이 아는 코드 모양 셋 포함) · override 키 유일 검사. ② 재시도는 `format:MCP 미연결` 에서만 제공자를 빼고 `violation:hook` 은 재시도 없음(#711) — V-2c 로 분리. ③ 형식 불일치는 도구 결과 실패 + stderr(probe 는 배포 때만 · 수집기는 adv stdout 을 읽지 않는다). ④ 쓰기 0 시험 세 겹(이름 · 쓰기 API 정적 금지 · 읽기 전용 고정값 디렉터리). ⑤ S0 판정 출처는 C4 probe 하나(CI 는 fit DB 본문을 못 본다). ⑥ 수집기 형식 고정값 시험은 필수 `verify` 에.

**확정 P-b (Q141 = 예).** 비데이터 제공자 셋 모두 "작은 읽기 몇 개" 이고 같은 서버 같은 HOME(V28)이다. 상주 프로세스를 늘리면 012 R-15 결합이 하나씩 붙는다(014 §3-A 선례).

**`local` 리더 원칙 (V28 이 만든 것).** 700/600 은 장벽이 아니다 — 범위는 코드가 지킨다:
1. **읽을 위치와 허용 선언 위치는 리더 코드의 상수**다(AU:40 I1). 예: ops 리더 = `deploy/ops/domain.json` 에서만 열린다 · 다른 선언이 `reader: "ops"` 를 고르면 그 선언은 `unavailable why=reader-not-allowed`. 리더가 실제로 읽을 경로는 **통합 층이 쓰는 mcp-config 의 args/env 로 호스트에 넘긴다**(V37 — `PLEIADES_PRIVATE_DIR` 은 CLI 자식 env 에 없다 · 통합 층 코드가 정하므로 이 원칙과 충돌하지 않는다 · AU:13). 선언 JSON 에는 경로를 두지 않는다.
2. **필드 허용 목록** — 알 수 없는 필드는 버리고 **개수를 센다**(아래 3).
3. 읽기 리더는 읽기만(열기 플래그 · 잠금 없음) · 크기 상한 · 깨진 줄은 건너뛴다. 모르는 필드 · 빠진 필드 · 깨진 줄(형식 불일치)은 **운영 중 보이는 길 둘**로 낸다(AU2:33 — r2 의 "probe 줄" 은 adv 배포 때만 돌고 로그 stdout 은 수집기가 읽지 않는다 · V40): ① **그 제공자의 도구 결과를 실패로** 돌린다(모델이 "확인하지 못했다" 로 답한다 — 012 BASE 규칙) ② 불일치 줄을 **stderr** 로(수집기 분류표가 경고로 셀 수 있는 자리 — 분류 행 추가는 수집기 재설치 동반이라 별건). probe 의 `형식 불일치 N` 은 배포 때 보조(AU:17).
4. 형식 계약 시험은 제공자 쪽 시험과 **같은 고정값**을 쓰고, **제공자 쪽 시험이 필수 CI 안에서 돈다** — hermes `state.json` 고정값은 `apps-hrm`(필수) · 수집기 `events.jsonl` 고정값은 CI 밖(V42)이라 **필수 `verify` job 에 넣는다**(도메인 계약 시험과 같은 예외 · AU2:36). 아니면 형식을 바꾸는 PR 이 고정값을 갱신하지 않아도 막히지 않는다.
5. **제안(쓰기) 호스트는 읽기 리더와 섞지 않는다** — §8-3.
