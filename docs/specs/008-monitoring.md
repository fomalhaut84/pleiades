> - **판정:** 수집기가 그 파일의 **수정 시각만** 본다(내용은 읽지 않는다). `aliveStaleMin`(10분) 넘게 그대로면 `<app>·bot · gateway · stale` = `장애`(상태형 · 복구 있음). 파일이 없으면 판정하지 않는다(릴리즈 전 · Discord 미설정) · 배포 보류 중에도 판정하지 않는다 · stat 이 ENOENT 밖으로 실패하면 `alive-read:<app>`.
> - **이 판정은 "Discord 연결 유지" 를 본다 — "응답 가능" 이 아니다.** ACK 는 연결만 살아 있으면 약 41초마다 오므로, 연결은 살아 있는데 봇이 일을 못 하는 경우는 표지가 정상으로 남는다: ① 메시지 수신 권한 거부(4014)로 버튼만 받는 모드로 강등된 경우(메시지 명령을 받지 못한다 — 강등 줄은 stderr 판정이 따로 잡는다) ② 핸들러·AI 호출이 멈춰 답이 나오지 않는 경우(이번 판정으로 잡히지 않는다). 잡는 것: 좀비 연결(ACK 끊김) · IDENTIFY 보호에 막힘 · 치명 close 코드로 멈춤 · 재접속 계속 실패.
> - **한계:** Discord 를 일부러 끄면 낡은 표지가 남아 `장애` 가 계속 난다 — 그 파일을 지운다(런북 §3). 침묵 감지 24h 는 그대로 두고, 생존 판정이 며칠 안정적으로 돈 뒤 bot 역할 침묵을 끌지 다시 본다.
> - 되돌리기: revert(**즉시**) · 표지 파일 삭제(**즉시** · 판정만 멈춘다).

**이 표의 "없음" 행은 모니터가 서비스와 다른 OS 사용자일 때만 강제된다** — 같은 사용자면 `.env`·pm2 소켓이 그대로 닿는다. 다른 사용자면 pm2 데몬·`claude` 로그인(서비스 사용자 `~/.claude`)이 갈린다 — **Q97**.

**I-3 은 이 개발 세션의 규칙이다** — 서버의 모니터는 advisor 처럼 서비스의 일부이고 사용자가 배치한다(#242 의 "서버에 닿는 것은 CI" 와 같은 구분). 이 세션은 여전히 서버에 닿지 않는다.

### 4-7. 분석 에이전트

- **읽기 전용 도구만** — 셸이 아니라 좁은 도구(이벤트 조회 · 지문별 로그 발췌(마스킹 뒤) · 배포 체크아웃 코드 읽기)를 MCP 로 준다. 원문 접근 범위가 곧 유출 범위다
- **입력은 데이터다** — 로그에는 외부가 쓴 텍스트(봇에 온 메시지 · 외부 API 오류 본문 · WebFetch 결과)가 섞인다. 그 안의 지시를 따르지 않는다는 것을 시스템 프롬프트와 도구 설계 양쪽에 둔다(§5 G-3)
- **비용** — 지문당 분석 1회 · 하루 상한 · 호출당 `--max-budget-usd` · advisor 와 같은 `claude` 계정이면 쿼터를 나눠 쓴다(같은 OS 사용자면 강제 · Q97) · 모노레포 상위 컨텍스트 차단(#247 의 `claudeMdExcludes`/격리 인자와 같은 방식)
- **산출 형식** — 원인 추정(확신도 포함) · 근거(이벤트 ID · `file:line`) · 해결 방안 · 재현 조건. 확신이 낮으면 "추정" 으로 적고 이슈를 만든다(사람이 버린다)

## 5. 이슈 정책

두 저장소의 규칙이 다르다. **비밀은 어디에도 쓰지 않는다**는 것만 같다.

### 5-1. 비공개 ops 저장소 (모니터링이 쓴다)

| 항목 | 규칙 |
|---|---|
| 비밀 | **금지** — 토큰 · 키 · 비밀번호 · env 값 · 세션·쿠키. 비공개여도 쓰지 않는다(토큰 유출 · 접근자 추가 · 이후 공개 전환 · 플랫폼 측 열람 가능성) |
| 개인 도메인 값 | 원인 설명에 **필요한 만큼만** — 금액·종목·건강 수치·메시지 원문은 원인이 그 값일 때만 · 발췌는 짧게 |
| 인프라 세부 | 허용(경로 · 프로세스 · 포트) — 단 계정·자격 증명 식별자는 쓰지 않는다 |
| 로그 발췌 | 허용 — **마스킹 뒤 · 줄 수 상한** |
| 기계 검사 | **적용 대상: ops 이슈 · Discord · 대시보드 게시**(§4-1·§4-3). 게시 전: ① 비밀 값 일치 차단 — 모니터는 env 원문을 갖지 않으므로(§4-6 "없음") **서비스 사용자 쪽에서 만든 해시·지문 목록과 대조**(생성 위치는 Q97) · **정정 (2026-11-10 · #564): 단계 1 은 같은 사용자라 비밀 키 값만 메모리에서 대조하고(포트 · `production` 같은 비밀 아닌 값은 대조하지 않는다 — 거짓 차단) · 하나라도 못 읽으면 게시하지 않는다** ② 토큰 형식 패턴 ③ 길이 상한. 걸리면 게시하지 않고 **본문 없는 고정 문구(지문 · 차단 사유 코드만)** 를 Discord 에 보낸다(재작성 재시도 없음 — 우회 학습 경로) |
| 중복 | 본문 지문 표식(`<!-- ops-fp:… -->`) · 열린 같은 지문 = 코멘트(횟수 · 최근 시각) · 중복 판정은 **기록기 계정이 만든 이슈의 표식만** 본다 |
| 라벨 | 앱 · 심각도 · 상태(`분석됨`·`승격됨`·`해결 확인`·`버림`) |
| 상한 | 하루 새 이슈 수 상한 |
| 종료 | 수정 태그 배포 뒤 같은 지문이 관찰 기간 동안 없으면 기록기가 `해결 확인` 코멘트 후 닫는다 · 재발이면 새 이슈 + 원 이슈 참조 |

### 5-2. 공개 pleiades (승격 — 개발 쪽이 쓴다)

공개 저장소에 쓴 것은 되돌릴 수 없다(편집 이력 · 알림 메일 · 공개 이벤트 아카이브). **사전 차단만 있다.**

| 규칙 | 내용 |
|---|---|
| **P-1 등급** | **A** 저장소 코드만으로 설명되는 결함 → 승격 가능 · **B** 개인 데이터·인프라 세부가 있어야 설명되는 것 → 코드 측면만 뽑아 A 로 다시 쓸 수 있을 때만 · **S** 보안 → 고칠 때까지 공개하지 않는다(ops 저장소에서 처리 · 공개는 수정 릴리즈 뒤 요약) · **N** 코드로 할 일 없음 → 승격하지 않는다 |
| **P-2 허용 필드** | 앱·역할 · 심각도 · 발생 날짜(시 단위)·횟수 · 배포 태그 · 오류 클래스·코드 · 저장소 상대 `file:line`·저장소 프레임 스택 · 원인 추정·해결 방안 |
| **P-2 금지** | 절대 경로 · 호스트·도메인·IP·서버 포트 · OS 사용자·계정·이메일 · 텔레그램·Discord ID · DB 이름 · env 값 · 토큰 형태 · **로그 원문 줄** · 요청·응답 본문 · 사용자 메시지 · 개인 도메인 값 · 외부 계정 식별자 |
| **P-3 검사** | 승격 본문을 게시 전 검사기로 통과시킨다(패턴 · 길이) — 방식은 **Q93** |
| **P-4 사람** | 승격은 개발 쪽이 사용자와 함께 하는 일이다 — 자동 승격 없음 |
| **P-5 참조** (중복·갱신·종료는 §5-1 로 옮겼다) | 공개 쪽은 ops 이슈를 **비링크 `ops#N`** 으로만 적는다(`fin#N`·`fit#N` 관례 · I-2 와 같은 형식). ops 쪽은 공개 이슈를 자유롭게 링크한다 |
| **P-6 누출** | 비밀이 게시됐으면 **교체가 되돌리기**다(사용자) → 이슈 삭제(관리자) → 기록에는 판정만 |

> **정정 (2026-11-10 · #253 · Q93 이행) — P-3 검사기 = `tools/ops/promote_check.py`.**
> - 쓰는 법: 승격 본문을 파일로 쓰고 `python3 tools/ops/promote_check.py <파일>`(또는 `-` stdin). **통과 exit 0 · 차단 exit 1 · 입력·금지 값 파일 오류 exit 2.** 차단하면 **줄:열과 사유 코드만** 출력하고 걸린 값은 다시 쓰지 않는다.
> - 패턴(P-2 금지 중 기계로 잡히는 것): 절대 경로(알려진 최상위 디렉터리 · 그 밖은 세 토막 이상 — `/api/` 라우트 제외) · IPv4·IPv6 · 이메일 · 허용 목록 밖 호스트·도메인(스킴 무관 URL · 점 있는 이름은 전체를 잡은 뒤 마지막 라벨이 일반·사설 TLD 또는 두 글자 국가 코드면 — 파일 확장자 `md`·`ts` 등 제외 · 허용 목록은 접미 일치) · URL 계정 정보(`user:pw@`) · env 값(`KEY=값` · 따옴표 포함 · Yahoo 환율 심볼 `XXX=X` 제외) · 9자리 이상 숫자열(Discord·텔레그램 ID 형태 · 14자리 마이그레이션 이름 `YYYYMMDDHHMMSS` 제외) · 토큰 형태(텔레그램·Discord 봇 · JWT · GitHub · `sk-` · AWS · Slack · 웹훅·인터랙션 경로 · 영문+숫자 32자 이상이고 `-`·`_` 로 나눈 한 조각이 16자 이상 — 16진수만인 커밋 SHA · 하이픈 파일 이름은 허용) · 로그 원문 줄(타임스탬프·pm2·`[LEVEL]` 접두) · 초 단위 시각. **경계는 ASCII 다** — 한글 조사·문장 끝 마침표가 붙어도 잡는다(파이썬 `\w` 는 한글을 단어 문자로 본다 · #253 사전 리뷰).
> - **길이 상한 6000자**(사용자 2026-11-10) · `--max-chars` 로 한 번씩 올린다.
> - **저장소에 둘 수 없는 금지 값**(서버 도메인 · DB 이름 · 계정명 · 서버 포트 등)은 비추적 파일 **`tools/ops/deny.local`**(`.gitignore` · 한 줄에 하나 · `#` 주석 · 대소문자 무시) 또는 env **`PLEIADES_PROMOTE_DENY_FILE`** 이 가리키는 파일(사용자 2026-11-10). 4자 미만 값은 건너뛴다(모든 줄에 걸린다). 파일이 없으면 경고하고 패턴 검사만 한다 — 값 목록은 사용자가 채운다. `localhost` 같은 점 없는 단어 호스트는 URL 밖에서는 패턴으로 못 잡으니 이 파일에 둔다.
> - **줄 단위 검사다** — 줄바꿈으로 쪼갠 토큰은 못 잡는다(금지 값만 줄바꿈을 지운 본문으로 한 번 더 본다). 상한을 넘으면 패턴 검사 없이 TOO_LONG 만 낸다.
> - **검사기는 보조다.** 사용자 메시지 · 요청·응답 본문 · 개인 도메인 값 · 외부 계정 식별자는 패턴으로 다 잡히지 않는다 — 통과해도 P-4 사람 확인을 거친다.
> - 테스트: `python3 -m unittest discover -s tools/ops`(`workflow.md` 8절 `tools/` 행). 되돌리기: 스크립트 삭제 (**즉시**).
