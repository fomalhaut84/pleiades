**Q16·Q18 은 답을 받은 것이 아니라 질문 자체가 사라졌다.** 둘 다 *"경로가 바뀐다"* 를 전제로

### 2-1. 결정 요약 한 줄

> **저장소는 옮기지 않는다. 브랜치를 하나 더 펼친다.**
> 실서비스용 체크아웃(`~/workspace/myFinance` = `dev`, `~/workspace/myFitness` = `main`)은
> 제자리에 남고, 통합 작업용 체크아웃(`repos/*` = `integration/pleiades`)이 pleiades 안에 생긴다.

### 2-2. worktree 는 A-mv 와 A-clone 을 **모두 지배한다**

이 표가 이 문서의 중심이다.

| | **A-clone** | **A-mv** | **worktree (채택)** |
|---|---|---|---|
| 원본 체크아웃 | 남음 | **사라짐** | **남음 — 서비스 유지용 브랜치가 제자리에** |
| 저장소 벌 수 | **2벌 — 분기 가능** | 1벌 | **1개, 작업 디렉터리 2개 — 분기 불가** |
| `~/.claude` 경로 키 3곳 (`projects/` · `~/.claude.json` · `history.jsonl`) | **고아** | **고아** | **영향 0** |
| `git clean -ffdx` 사고 | 원본 삭제 후에는 편도 | **편도 (유일본 삭제)** | **아님 — 원본에서 재생성** |
| `.next/cache` 콜드빌드 | 신규 1회 | **2회 (이동 + 되돌림)** | **손실 0** (원본 캐시 warm 유지) |
| 디스크 | **+3.06 GB** | 0 | **90 MB 실측** (`node_modules` COW) |
| gitignored 필수 파일 | **수동 복사 6종** | 0 | **수동 복사 5종** (§4-2) |
| 되돌리기 | 새 디렉터리 삭제 | `mv` 2회 + 참조 12곳 + 콜드빌드 ×2 | **`git worktree remove`** |

**지배 논증.** A-clone 이 주는 유일한 장점("원본을 안 건드린다")을 worktree 도 준다. 그런데
worktree 는 A-clone 의 대가 — 3.06 GB, 저장소 2벌의 **분기 가능성**, 시크릿 2벌 — 을 치르지 않는다.
A-mv 가 주는 유일한 장점("디스크 0, 이력 통째 보존")도 worktree 가 90 MB 로 거의 준다.
그런데 worktree 는 A-mv 의 대가 — `~/.claude` 키 고아화, 콜드빌드 2회, `clean -ffdx` 편도 —
를 치르지 않는다. **두 옵션 각각에 대해 worktree 가 약하지 않고 어딘가 강하다.**

**"분기 불가"가 가장 값싸게 얻은 것이다.** A-clone 의 진짜 위험은 3 GB 가 아니라
*"같은 코드가 두 벌 있고 어느 쪽이 정본인지 사람이 기억해야 한다"* 였다. worktree 는
**저장소가 물리적으로 하나**여서 그 상태가 만들어질 수 없다 — 같은 브랜치를 두 디렉터리에
체크아웃하는 것을 git 이 거부한다.

### 2-3. 003 §2-3 의 "단계 4 를 앞당기지 말라" 근거 3개는 worktree 에 걸리는가 — **걸리지 않는다**

003 §2-3 은 모노레포(변형 B)를 앞당기지 말아야 할 근거 3개를 세웠다. **셋 다 B 전용이다.**

| # | 003 §2-3 의 근거 | worktree 에 걸리나 | 근거 |
|---|---|---|---|
| **1** | B2 는 실서비스 2개의 **배포 파이프라인 동시 재설계** + **릴리즈 격리 상실**(002 Q2 미결) | **아니오** | **M4 + 감사 §4.** 배포는 `GitHub Release → deploy.yml → appleboy/ssh-action → 서버가 GitHub 에서 직접 fetch/checkout`(fin `deploy.yml:54,78,96,97,127` / fit `:54,78,86,87,89`). 로컬 머신은 배포 경로에 등장하지 않고, **로컬에 pm2 미설치 · 4100/4200 리슨 없음** — 깨질 로컬 배포 절차가 아예 존재하지 않는다. 릴리즈 격리는 **저장소·원격·태그가 여전히 2벌**이므로 상실 사유가 없고, worktree 는 오히려 **실서비스 브랜치 체크아웃을 물리적으로 별도 디렉터리에 남긴다** |

> **주의 — 이 판정은 "worktree 가 공짜"라는 뜻이 아니다.**
> 003 §2-3 이 worktree 에 안 걸리는 이유는 **worktree 가 싸서가 아니라, §2-3 이 로컬 배치를
> 검토한 적이 없어서다.** worktree 의 실제 청구서는 §4-3 과 §6 이고, 그중 가장 큰 항목은
> **하네스 통합이 선결 조건으로 승격된 것**(§6-1)이다.

### 2-4. **worktree 는 모노레포로 가는 계단이 아니다**

002 단계 4(B2)는 **여전히 별개 결정**이고 진입 조건도 그대로다 —
**도메인 #3(캘린더)을 실제로 붙일 때**, 병렬 조건으로 **1a 운영 중 패키지 수정 PR 2개짜리
왕복이 반복적으로 성가실 때**(002 §4 정정 블록 · 003 §2-4). 되돌리기 등급 **높음**도 그대로다.

worktree 를 "모노레포로 가는 계단"으로 정당화하면 §2-3 을 우회해 B 를 앞당기는 것과 같아진다.
**worktree 는 자기 이득(세션 편의 + 하네스 통합의 전제)으로만 정당화된다.**

**`repos/*` → `apps/*` 이행 시 승계되는 것:** 디렉터리 배치와 `.gitignore` 한 줄은 **승계되지
않는다**(worktree 는 제거되고 `apps/` 는 pleiades 저장소의 tracked 경로가 된다). 승계되는 것은
**`integration/pleiades` 브랜치에 쌓인 커밋과 그 이력 하나뿐**이며, 그것이 단계 4 의 이력 병합
(subtree/merge) 입력이 된다.

### 3-3. Grep 도구는 차단되지 않는다 — **루트 traversal 제외일 뿐**

감사 §3 은 "`repos/` 를 ignore 하면 Grep 이 못 본다"고 했으나, 오케스트레이터 실측에서
**경로를 명시하면 찾는다.**

| 검색 | 결과 |
|---|---|
| 루트 검색(경로 미지정) | ❌ |
| `path: repos/inner` | ✅ `FOUND:repos/inner/src.txt` |
| `path: repos/` | ✅ |

→ **규칙 한 줄로 처리된다:** *"`repos/` 하위를 검색할 때는 `path` 를 명시한다."*

### 3-4. **방법론 경고 — `grep -r` 의 binary 스킵이 0건 오탐을 만들었다**

`01_surveyor_layout.md` M3 과 감사 1차 스캔이 **둘 다 `.next/cache` 를 0건으로 보고**했다.
원인은 하나다: **`grep -r` 이 그 파일들을 binary 로 판정해 건너뛴다.**

```bash
# 이 저장소의 절대경로 측정 표준 플래그 — 이후 모든 측정에 붙인다
grep -rn --binary-files=text -- "/Users/sagan/workspace" <path>
```

**이 경고는 이번 건에 한정되지 않는다.** `docs/research/measured-facts.md` 의 **기존 grep 기반
"0건" 결론들이 같은 결함을 가질 수 있다** — 특히 M3 의 *"myFitness 소스·설정 전체 0건"*,
M4 의 *"`rsync`/`scp` 0/0"*. 재검증 전까지 그 0 들은
**"텍스트 파일 범위에서 0건"** 으로 읽어야 한다. → §6 Q22.

### 4-1. 옵션 사다리 (되돌리기 비용 순) — 기록용

집행이 끝났으므로 이 표는 선택지가 아니라 **비교 기록**이다.

| | 옵션 | 되돌리기 등급 | 되돌리는 행위 | 디스크 | 채택 |
|---|---|---|---|---|---|
