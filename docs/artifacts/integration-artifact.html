발견 1

"통합"은 하나가 아니라 두 개의 축이다

축 A — 하네스·세션 통합: Claude Code 를 어떻게 쓰느냐의 문제. 스킬·에이전트·규칙·메모리·세션. 코드는 한 줄도 안 건드린다.

발견 4

알림 채널 교체는 절반만 싸다

아웃바운드(알림 발신)와 인바운드(봇 명령)의 비용이 완전히 다르다. 이걸 구분하지 않으면 비싼 쪽을 두 번 하고 버리게 된다.

아웃바운드 fin 3,378 + fit 1,212줄 · 인바운드 fin 3,968 + fit 1,843줄
전송 호출 fin 149 / fit 61 — 전부 인바운드 쪽에 몰려 있다

아웃바운드는 이미 한 지점을 지난다 — myFinance 는 bot/utils/telegram.ts, myFitness 는 bot/notifications/send.ts. 알림 모듈 16개/5개 중 원시 전송을 직접 하는 건 각각 1개뿐이다. (같은 역할이 다른 파일에 있는 것 — 스킬 이름이 갈린 것과 정확히 같은 쌍둥이 패턴이고, 001 이 측정한 드리프트 142줄이 그 값이다.)

그래서 인바운드를 저장소별로 각각 Discord 로 옮기면 안 된다. 비싼 작업을 두 번 하고, 통합할 때 버린다. 아웃바운드만 먼저 옮기고 인바운드는 단일 봇까지 텔레그램으로 둔다.

A2

메모리 공유 + 통합 어드바이저

되돌리기: 즉시단계 0 · 2

두 프로젝트의 autoMemoryDirectory 를 같은 경로로 지정해 한 벌의 auto memory 를 쓴다. 동시에 mcp-config.json 에 두 MCP 를 함께 등록해 어드바이저가 양쪽 데이터를 본다 (발견 3).

주의: MEMORY.md 인덱스는 세션 시작 시 200줄 / 25KB까지만 로드된다. 현재 myFinance 126줄 + myFitness 16줄 = 142줄, 여유 58줄. 도메인이 셋이 되면 이 여유로는 부족하다. 압축 선행이 필수다.

되돌리기: revert + restart

서로의 MCP 서버를 등록하고, --allowedTools 화이트리스트에 상대 도메인 도구를 등재하고, 시스템 프롬프트에 교차 도메인 사용 지시를 넣는다. 그다음 빌드 → pm2 restart → 텔레그램 /reset (기존 --resume 세션은 옛 도구 목록을 붙잡고 있다).
