## 주의사항

- **Release 발행 = 운영 배포다.** `gh release create` 는 곧 fin → fit 배포를 시작한다. 크론 시각(매시 :00 · fin 15:35·15:40 · 월 07:00 · fit 웹 싱크 정각 · 미국장 브리핑 23:00)을 피해 발행한다. 마이그레이션 든 태그는 `--prerelease`.
- **릴리즈 PR 은 봇 결과를 확인한 뒤 태그를 붙인다** — 오늘 #296 은 봇이 끝나기 전에 머지됐고 P2 가 늦게 왔다(→ #297). 매 머지 뒤 봇 결과를 다시 본다(메모리 `feedback_check_bot_before_merge_ok`).
- **I-9 가 바뀌었다** — 저장소 수준 secrets 0 · environment `production` 에 `DEPLOY_SSH_KEY`·`HOST`·`USER`·`KNOWN_HOSTS`(PORT 없음 = 22)만 · 배포 대상 = 태그 `v*` 하나. `pleiades-resume` 이 매 세션 점검한다(#300 으로 zsh 오탐 수정).
- **서버 상태:** 두 체크아웃 `v1.0.6` · `~/pleiades-private/`(700 · 원본 로그 · `inplace-<app>-last-ok` · `pending` · `deploy.lock`) · authorized_keys 에 `pleiades-deploy` forced command 줄. **R-8 로 `v1.0.2` 이하에 가면 `ssh-deploy.sh` 가 사라져 자동 배포가 닫힌다**(안전 쪽).
- fin 제자리 재배포의 프로브 오류 1회(웹 재기동 ≈2 s)는 4번 중 3번 — 판정 영향 없음.
- 자동 배포 알림은 **실행 중인 `ssh-deploy.sh` 판**으로 돈다 — 그 파일을 바꾸는 릴리즈는 다음 배포부터 효과.
- 세션 시작 관측: dev `8f55504`(로컬 behind 2 → ff) · 수용 fin `3685b2ca138c` · fit `35a04d78e532` 최신(동결) · secrets 0. **인계보다 현재 상태를 믿는다.**

## 재현이 필요한 절차

- **릴리즈:** 버전 PR(4파일 · `npm version X --no-git-tag-version` 루트 + `packages/notify`) → 릴리즈 PR(dev → main · 봇 게이트) → 머지 확인(부모 2 · main 트리 == origin/dev) → `git tag vX && git push origin vX` → 런북 A(앱 경로로) → `gh release create --notes-file`(릴리즈 PR 본문에서 추출) → `gh run list --workflow deploy.yml` 로 완료 대기 → `gh run view <id> --log | grep` 로 판정 양식·`notify-deploy:` 줄.
