## 주의사항

- **세션 시작 때 현재 상태를 다시 본다.** 이 노트보다 `git log` · `gh pr list` 가 정본이다.
- **운영 발행은 사용자 명시 지시를 받는다.** "릴리즈 PR 머지 = 배포 의지" 로 발행하려다 권한 분류기가 막았다. "v1.7.0 발행해" 뒤에는 통과했다. `workflow.md` 의 "Claude 발행" 문구와 다르니 판단이 필요하면 사용자에게 묻는다.
- **봇 👀 는 통과가 아니다.** 👍 또는 리뷰가 올 때까지 기다린다. #490 에서 👀 뒤 P2 가 왔다.
- **`apps/*` 를 바꾸면 `deploy` 테스트도 돌린다** — `.env.example` 키는 `deploy/env/*.template` 에도 있어야 한다. CI 에 없어 PR 에서 드러나지 않는다(약 9분 · #487 사전 리뷰가 잡음).
- **zsh:** `$c` 를 나누지 않고 `$S:a` 를 경로 수식어로 읽는다. 여러 단계 명령은 `set -euo pipefail` 인 bash 파일로 돌린다. 이번 세션 실수 2건(빈 본문으로 PR 편집 · 일부 파일만 버전 커밋)이 여기서 나왔다. PR 본문을 고칠 때 파일이 비지 않았는지 먼저 본다.
- **버전 올릴 때 잠금 파일은 이름으로 지정한다.** 서드파티에 같은 번호가 있다(`sourcemap-codec` 1.6.0).
- **IDE 에서 선택한 줄은 메시지에 함께 첨부된다.** 이번에 `.env` 의 키 줄이 세션 안으로 들어왔다. 값은 저장소 · PR · 로그에 쓰지 않았다. 사용자가 재발급하지 않기로 했다.
- **로컬 `apps/finance/.env` 에 OpenDART 키가 있다.** `tools/local/check_env.py` 는 이 키를 막지 않는다. 격리 규칙에 정한 바 없으니 다른 앱 키처럼 비울지는 사용자가 정한다.
- **로컬 Node 20 은 `yahoo-finance2` 4.x 지원 범위 밖이다** — 인스턴스마다 경고가 나고 예외는 없다. CI `apps-fin` · 서버는 Node 24. esbuild `--target=node20` 은 그대로 뒀다(번들 로드 확인).
- **nginx 파일은 배포 스크립트가 적용하지 않는다.** 저장소에서 고쳐도 운영에 수동 반영이 필요하다(검색 기준).
- **fit web 오류:** 배포마다 재시작 때 나는 줄로 보이고 v1.7.x 와 무관하다. **미상 2건:** 하루 내내 반복되는 `The ...` 줄의 내용 · 10-31 · 11-01 의 일시 급증(지금은 재발 없음). 수치는 공개 기록에 쓰지 않는다.
- **서버 스크립트:** `.server-scripts/13-*` · `14-*` 를 추가했다(미추적 · 유지).
- **스크래치:** 세션 스크래치에 임시 사본 폴더가 남아 있다(삭제 안전 검사로 지우지 않음). 저장소와 무관하다.
