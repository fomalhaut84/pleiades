## 주의사항

- **세션 시작 때 현재 상태를 다시 본다.** 관측(이 세션 끝): `dev` = `main` 내용 + 이 노트 PR · 운영 `v1.8.1`.
- **원격(클라우드) 세션의 git push 는 지정 브랜치 하나만 받는다.** 다른 브랜치 push · 태그 push 는 원격에서 끊긴다(`commit_refs_rules` · `unexpected disconnect`). 우회:
  - PR 브랜치 → 지정 브랜치에 커밋·push 한 뒤 GitHub API `create_branch` 로 `<type>/<issue>-<n>` 를 만들어 그것으로 PR.
  - 태그 · Release → 세션에서 만들 도구가 없다. **사용자가 웹에서 발행**(Tag 새로 만들기 · target `main` · 노트는 세션이 준다).
- **PR head 를 지정 브랜치(`ccr-…`) 그대로 두면 머지가 안 된다**(#495). 원인은 확인하지 못했다(ruleset 을 못 읽는다) — 저장소 관례 이름으로 연다.
- **GitHub API 가 500 을 돌려줘도 실행됐을 수 있다.** #495 닫기가 500 이었지만 닫혔다. 다시 하기 전에 상태를 읽는다.
- **squash 머지 뒤 지정 브랜치를 `dev` 로 다시 맞추면 force push 가 필요하다.** 원격 커밋이 이미 `dev` 에 squash 로 들어간 것만 있을 때만 `--force-with-lease=<브랜치>:<sha>` 로 한다. 안 할 거면 로컬을 원격 브랜치에 맞춰 둔다(Stop 훅이 unpushed 를 막는다).
- **사용자는 CI 가 끝나기 전에 머지할 수 있다**(#498 · apps 잡 진행 중 머지). 같은 커밋이 릴리즈 PR 에서 다시 돌았고 통과했다.
